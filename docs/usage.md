# Usage

The in-app **Guide** covers the same ground for staff. This page is the reference version.

## Main flow

1. **Delivery:** set the date and who received it. Optional: expected pallets, trailer number, seal in, seal out (the three boxes sit side by side only when the Delivery card is at least 520px wide, enough for an 11-character seal number in each; otherwise the trailer box is full width with the two seal boxes under it, since build 45), notes (up to 2000 characters). Previously used names appear as one-tap buttons. For the next trailer on the same day, **Clear trailer, seals and notes** under the notes box empties those four boxes and keeps the rest (build 53, see [below](#clear-trailer-seals-and-notes-build-53)). Since build 48, if seal in and seal out are the same number, or have different lengths (spaces and upper/lower case are ignored), a note under the seal boxes asks you to check them (see [Seal check](#seal-check-build-48)). Since build 66 Expected pallets has **−** and **+** buttons either side of it, the seal boxes open the phone's number keypad, and the trailer number is put into capitals as it is typed (see [Delivery boxes](#delivery-boxes-build-66)).
2. **Manifest (optional):** open **Manifest check** and add the manifest by photo, PDF or typing, before scanning.
3. **Log pallets:** choose the type (BB, FMCG, FPP, Mixed), tick FSDU if needed, scan or type the LPN, press Add or Enter. Since build 66 a typed LPN is put into capitals without spaces or dashes when it is LPN-shaped ("vlt 0040-40265" goes in as VLT004040265), and a list of LPNs can be pasted into the LPN box to add them all (see [Paste, mute, copy and keyboard shortcuts](#paste-mute-copy-and-keyboard-shortcuts-build-66)).
4. **Export:** **Export → Download (Excel)**, **Email PDF** or **Print** (the menu's fourth item, **Blank tally sheet**, prints an empty paper sheet; see [Exports](#exports)). The log then shows "Exported at hh:mm" and offers **Start a new delivery?**
5. **Start new delivery:** saves the delivery to Saved deliveries and clears the page (Undo is offered). If the delivery hasn't been exported since its last change, the first press shows a reminder; pressing again goes ahead.

When two people unload one trailer, each can log on their own phone and then put all the pallets on one phone with **Share log** before exporting (build 66, see [Share log](#share-log-build-66)).

If the app is opened on a later day with a delivery that has pallets but was never exported, a reminder card at the top offers **Export now** (build 62, see [Reminder about a delivery not exported](#reminder-about-a-delivery-not-exported-build-62)).

## Logging behaviour

- The type stays selected after each pallet (unless "Keep the last pallet type" is off); FSDU clears each time.
- Before adding, an LPN is checked. A warning with **Skip / Add anyway** appears when it is:
  - already in the log;
  - not 1–3 letters followed by digits;
  - using a prefix outside the prefix list;
  - the wrong number of digits: 9 or 10 for most LPNs (usually 3 letters), but 10 or 11 for `IM` numbers (full pallet picks, 2 letters). The warning says, for example, "has 12 digits (usually 9 or 10)" or, for `IM`, "has 9 digits (IM numbers have 10 or 11)". Since build 39 an 11-digit `IM` number is not warned about.
- While a warning is waiting for an answer, another LPN typed or scanned into the box (a hardware scanner presses Enter on its own) is not lost and not added: it stays in the box, selected, with the message "Answer the check first (Skip or Add anyway), then add <LPN>." and the warning sound. After Skip or Add anyway, press Enter (or Add) to add it; the next scan replaces it, because it is selected. Since build 41.
- **Escape** skips a waiting warning, the same as **Skip**. It does nothing while the Guide, Changelog, Settings or Saved deliveries panel or the install box is open, or while another box (for example an LPN being edited in the table) has the keyboard; it does work in the LPN box.
- Each add shows "Added #n: LPN · type", plus "✓ on manifest" or "⚠ NOT on manifest" while a manifest is loaded. Since build 66 the type in that note is a small badge in the type's colour (BB, FMCG, FPP or Mixed) with black text, so a wrong type stands out at a glance.
- On phones the entry bar shows `n logged`, `n of expected logged`, or `n of total on manifest`, and the Delivery card folds into one line after the first pallet once **Received by** is filled in (since build 66 it remembers whether you last opened or folded it; see [Help buttons, Simple view and other build 66 additions](#help-buttons-simple-view-and-other-build-66-additions)). Since build 56 the count uses the longest wording that fits the bar and is never cut off: with an expected number it tries `n of x logged`, then `n/x logged`, then `n/x`, then just `n`; with a manifest `n/total on manifest`, then `n/total`, then `n`; otherwise `n logged`, then `n`. It is chosen again when the phone is turned or the text size changes. Screen readers always hear the full wording (for example "12 of 40 logged"). Before build 56 it switched to the short form on any screen under 400px. On screens under 360px the gaps around the FSDU box, the count and ↶ are a little smaller to give the count room.
- The ↶ button next to the entry-bar counter (phones only) removes the most recent pallet, with Undo.
- Tap an LPN to edit it (each LPN is a button, so it can also be reached with Tab and opened with Enter or Space); Enter saves, Escape cancels, and since build 42 both put the keyboard back on that LPN. Change type or FSDU in the table; ✕ removes it. Undo appears after removing, editing or Clear all; since build 55 one edit gives one Undo bar for everything changed in it (LPN, description, damage and, since build 62, refused). Since build 62 the last 10 changes can be undone in turn (see [Undo for the last 10 changes](#undo-for-the-last-10-changes-build-62)). Tapping an LPN also opens the damage choices under it (see [Damaged pallets](#damaged-pallets-build-49)), the **Refused (sent back)** button after them (build 62, see [Refused pallets](#refused-pallets-build-62)), and the Description box for a pallet with no LPN, an FPP pallet (since build 56) or any pallet with a description (see [Pallets with no LPN](#pallets-with-no-lpn-build-55) and [FPP pallet descriptions](#fpp-pallet-descriptions-build-56)). Since build 56 the LPN edit box is at least 44px tall (38px before).
- **Undo bar:** shows the newest change that can be undone, with "(n earlier)" after it when there are older ones (build 62). It stays 20 seconds (9 before build 42), and doesn't go away while it has the keyboard focus. On phones (under 760px) it floats just above the entry bar, so it can be seen while logging; with the Manifest check open (the entry bar stepped aside) it shows at the top of the screen instead (since build 45; before, it sat near the bottom and could cover a results row), so it never sits over the results being worked on. While the Undo bar shows, the "Added" note appears above it instead of underneath; a new Undo bar hides any "Added" note that is showing.
- **Totals as filters (build 66):** the BB, FMCG, FPP, Mixed and FSDU totals above the log are buttons. Tapping one shows only those pallets (it sets the type or FSDU filter and clears the other one) and marks the total with a border; tapping it again shows all. Total and Refused aren't buttons. Screen readers hear each as its name and count, for example "FMCG 8", and whether it is pressed.
- Search and the type and FSDU filters only change what is shown (since build 66 the search has a **✕** to clear it, and adding a pallet clears it; see [below](#paste-mute-copy-and-keyboard-shortcuts-build-66)); totals always cover the whole log. While search, a type or (since build 66) the FSDU filter is in use, the line "Showing x of y pallets (counts above are for the whole log)." shows under the filters and is read out. FSDUs are counted separately and are not part of the total. Since build 62 refused pallets are left out of the total and the type counts too, and a **Refused** count (its number in the warning colour) is added after FSDU when there are any; the FSDU count only counts pallets that weren't refused.
- With Expected pallets set, the line under the totals reads "n of x expected" (counting every pallet in the log, refused ones included, since they came off the trailer) with "(n to go)" in the normal text colour while counting, turns green with "✓ all accounted for" when the count matches, and turns red with "(n more than expected)" only when there are more pallets than expected. When a manifest is loaded and Expected pallets equals the manifest count, this line is hidden, because the manifest progress line already shows the same count.
- On phones (under 760px wide) the pallet table has no scroll box of its own: it scrolls with the page, and the column headings stay pinned at the top of the screen while you scroll through it. Long LPNs wrap onto a second line instead of pushing the page sideways. On wider screens the table keeps its own scroll area (up to 60% of the screen height).
- The FSDU tick boxes in the table are 32px. On phones the FSDU tick box in the entry bar is 40px and the scan option buttons (Live scan, Scan by photo, Upload photo since build 64, No LPN) are at least 48px tall, for gloves (build 41; before, 32px and 42px). The Guide, Changelog and Settings buttons in the header are at least 44px tall on phones.
- On screens up to 620px wide the header buttons wrap onto a second line and share the row (each sized to its text) instead of pushing the page sideways, for example with Extra large text.
- On phones, a box or button that gets keyboard focus scrolls clear of the fixed entry bar instead of ending up behind it.
- **↓ Latest (build 66):** on a log of 8 or more pallets, once the newest pallet is out of view, a **↓ Latest** button shows at the bottom right (on phones just above the entry bar). Tapping it scrolls the newest pallet into the middle of the screen and puts the keyboard focus on its LPN. It steps aside while the Undo bar or the "Added" note shows. Screen readers hear it as "Go to the newest pallet".
- Since build 66 pulling down at the top of the page no longer reloads it (a reload used to stop the camera in the middle of a scan), and the phone's **Back** button closes the open Guide, Changelog, Settings, Saved deliveries or Share log panel, the install box or the report box instead of leaving the app. With the report box open over a panel, Back closes the report box first, then the panel.

## Paste, mute, copy and keyboard shortcuts (build 66)

**Typed LPNs are tidied.** An LPN typed into the LPN box, pasted, or changed in the LPN editor in the table is put into capitals with spaces and dashes taken out, but only when the result is LPN-shaped (1 to 3 letters, then digits). So "vlt 0040-40265" goes in as VLT004040265 and "run001830763" as RUN001830763. Anything else, such as "PO-12 ab" or another kind of barcode, is kept exactly as entered (and the usual check then asks about it).

**Paste a list of LPNs.** Pasting several LPNs into the LPN box adds them all at once, instead of putting the text in the box:

- The list can be split by new lines, commas, semicolons or tabs. A single line of LPNs with spaces between them (each 1 to 3 letters and at least 6 digits) works too. A space inside one LPN on its own line ("VLT 004040265") keeps it whole.
- One LPN pasted on its own goes into the box as usual, to be checked and added with Enter.
- Each pasted LPN is tidied as above and added with the type and FSDU chosen in the entry bar. FSDU clears afterwards, and an old search is cleared so the new pallets show.
- With warnings on (Settings), any LPN the usual check would ask about (already logged, not shaped like an LPN, a prefix not in the list, the wrong number of digits) is left out. The status line names up to 3, in plain words, for example "Not added: VLT004040265 is already logged; not-an-lpn doesn’t look like an LPN; RUN001830763 is already logged. Type or scan them to add them." More than 3 end with "; and n more". If none were added it starts "No pasted pallets were added." With warnings off, everything is added.
- The Undo bar says "Added n pasted pallets". Its one **Undo** takes away only those pallets, and keeps any added since.
- At most 300 LPNs are taken from one paste; the rest are ignored.
- While a check about another LPN is waiting, a paste adds nothing and says "Answer the check first (Skip or Add anyway), then paste again." The LPN box is emptied, so paste again after answering.
- Pasted pallets don't show the "Added" note or open the FPP Description box.

**Mute the beeps.** A speaker button sits at the right of the **LPN number** label in the entry bar. It is the same switch as **Settings → Play a sound when a pallet is added or a warning shows**, and is kept on this phone. Tapping it says "Beeps muted." or "Beeps on." in the status line; muted, the speaker shows a cross in the accent colour and its tooltip reads "Beeps muted: tap to turn them on". Vibration is not affected. After a tap (not a keyboard press) the cursor goes back to the LPN box, so the next handheld scan lands there rather than pressing mute again with its Enter. Since build 66, tapping a type button on a touch screen also puts the cursor back in the LPN box.

**Clear the search.** A **✕** inside the search box shows while there is a search. It clears the search, shows every pallet again and leaves the cursor in the search box. Adding a pallet (or pasting a list) also clears an old search, so the new pallet isn't hidden.

**Search by the last digits (commit `654e5e6`, live since `main` `14ac5a4`, 26 Nov 2026, still build 66; in the Android app from Android APK build 7, being built, not handed out yet).** The search box's placeholder reads "Search LPNs or last digits" (screen readers hear "Search LPNs, or the last digits of one"). A search of only digits, 3 or more of them, shows the LPNs that **end** with those digits, so you can type the last digits off a label: with `VLT004041210`, `VLT004121055` and `RUN001830763` logged, "1210" shows only `VLT004041210`, even though `VLT004121055` also has "1210" in the middle. If no LPN ends with the digits, every LPN that contains them anywhere is shown, as before (in the same example "2105" shows `VLT004121055`). Searches with letters, or of fewer than 3 digits, match any part of the LPN as before ("12" shows both VLT pallets). Spaces in the search and in the LPNs are ignored, and case doesn't matter. The Guide's section 3 (Log pallets) says "Searching just numbers (3 or more) finds the LPNs that end with them, so you can type the last digits off a label.", and the v4.0 Changelog's first bullet is now "Search by the last digits: typing just numbers (3 or more) finds the LPNs that end with them."

**Copy an LPN.** Three ways, each saying "Copied <LPN>." in the status line (and a short vibration when Vibrate is on):

- press and hold an LPN in the table for about 0.6 seconds (a finger or the left mouse button; moving more than a few pixels cancels it). The editor doesn't open;
- tap the LPN and choose **Copy LPN** in the row that opens (next to **Refused (sent back)** when that is on). Pallets with no LPN have no Copy LPN button;
- on a computer, put the keyboard focus on the LPN and press Ctrl+C (Cmd+C on a Mac), as long as no text is selected on the page.

If the phone won't allow copying, it says "Couldn’t copy <LPN> on this phone."

**Keyboard shortcuts on a computer.** With nothing typed into a box: **1** BB, **2** FMCG, **3** FPP, **4** Mixed, **F** ticks or unticks FSDU, and **/** goes to the search box (not in Simple view, where the search is hidden). A type change says "Type: FMCG for the next pallet." and FSDU "FSDU ticked for the next pallet." or "FSDU unticked." They do nothing:

- while the cursor is in a box (there the key is just typed);
- with Ctrl, Cmd or Alt held;
- while the Guide, Changelog, Settings, Saved deliveries, Share log, the install box or the report box is open, or the Export menu or an LPN's editor row is open;
- when the keys come less than 50 ms apart, as a handheld scanner types them, so the F and digits of a scanned LPN can't change the type or FSDU;
- when **Settings → Keyboard shortcuts on a computer** is unticked (it is ticked by default and kept on this phone).

Each shortcut waits 70 ms before acting, so a scanner's next key can cancel it. Ctrl+Z still undoes the newest change (see [Undo](#undo-for-the-last-10-changes-build-62)).

## Delivery boxes (build 66)

- **Expected pallets** has **−** and **+** buttons (at least 48 by 44px), so it can be changed without the keyboard. **+** on an empty box gives 1; **−** never goes below 0, and on an empty box does nothing except say "Expected pallets is empty: tap + or type a number." Each change is saved and said in the status line, for example "Expected pallets: 13."
- **Seal in** and **Seal out** open the number keypad on phones, as the seals used are digits only.
- **Trailer number** is put into capitals as it is typed, with the cursor kept where it was. While a phone keyboard is still building a word, it waits until the word is finished.

## Help buttons, Simple view and other build 66 additions

**? help buttons.** A small round **?** sits on the heading line of **Delivery**, **Pallet log** and **Manifest check** (the last one only while the Manifest check is switched on). It opens the Guide and moves to that part: "Set up the delivery", "Log pallets" and "Check against the manifest". The part is found by its title, not its number, so it still works when switched-off features renumber the Guide. The heading gets the keyboard focus. Each **?** is a 28px circle with a 44px tap area round it, and screen readers hear it as "Help with Delivery", "Help with Pallet log" or "Help with Manifest check"; the headings themselves keep their own names. Tapping the Manifest check's **?** doesn't open or close the Manifest check.

**Simple view (Settings).** **Settings → Simple view** (off by default, kept on this phone and in backups) is for people who only scan and export. While it is on:

- the **Manifest check** card (and its live "Manifest: n of x found" count in the log), **Share log**, the **Scan by photo** and **Upload photo** buttons, the Live scan tip, and the search box and type and FSDU filters are hidden. **Live scan** and **No LPN** stay;
- turning it on clears any search and filter that was in use;
- manifest numbers already in the Manifest check are ignored: no live count, no "on manifest" or "NOT on manifest" in the Added note, no manifest count in the entry bar. They are still there, and count again, once Simple view is turned off;
- tapping a total (such as **FMCG**) still shows only that type, with the "Showing x of y pallets" line;
- the **/** keyboard shortcut does nothing (the other shortcuts still work);
- Live scan's messages don't suggest the photo buttons, and a Share log QR code seen in Live scan says "That’s a code from another phone. To add its pallets, turn off Simple view in Settings, then use Share log."

Turning it off brings everything back as it was. The Settings label names only the parts that are switched on in the site settings.

**Empty log.** With no pallets, the log reads "**No pallets yet.** Pick the type, then scan or type the first LPN in the LPN number box." with a **Go to LPN number** button that puts the cursor in the LPN box. The text wraps on narrow phones.

**Handheld double scans.** If the same LPN is added again within 2 seconds of being added, and it is still the newest pallet in the log, the second one is ignored without a warning: the LPN box is emptied and the status line says "<LPN> was added a moment ago, so the second scan was ignored." This catches a scanner trigger pressed twice. After 2 seconds, or once another pallet has been added in between, the usual "already logged" warning asks as before. It only applies to what goes through the LPN box with Enter or **Add** (typed, or scanned with a handheld scanner); Live scan, the photo buttons and pasted lists use their own checks.

**Delivery details fold.** On a phone the Delivery card folds into one line after the first pallet when **Received by** is filled in. Tapping that line opens or folds it, and since build 66 the app remembers the choice on this phone (also in backups): left open, it stays open after a reload and after the first pallet of the next delivery; left folded, it opens folded after a reload whenever there are pallets in the log. Until the line has been tapped once, it behaves as before.

## Damaged pallets (build 49)

Tap an LPN in the log (or Tab to it and press Enter). As well as the LPN box for correcting the number, a row opens under the pallet: **Damage:** **None**, **Crushed**, **Wet**, **Other…**.

- **Crushed** or **Wet** marks the pallet straight away and closes the row.
- **Other…** shows a box ("What’s wrong?", up to 60 characters) with **Save**; Enter in the box saves too. An empty box isn't saved. If the pallet already has a note of its own, **Other…** opens with that text in the box.
- **None** removes the note.
- The current choice is shown pressed (red for a reason, normal for None).
- A change to the LPN typed in the box at the same time is saved together with the damage choice. **Escape** cancels both. Since build 55 both changes (and a description change) are named on one Undo bar and undone together.

A damaged pallet shows "Damaged: <reason>" in red under its LPN, with a red line on the left of the LPN cell; a long note wraps instead of widening the table. The Undo bar says "Marked <LPN> as damaged (<reason>)" or "Damage note removed from <LPN>", and **Undo** puts the old note back. The note is saved with the log, in saved deliveries and in backups. Changing it after an export counts as a change, so the log reads "Changed since it was exported…" and Start new delivery asks for a fresh export.

On exports each damaged pallet gets a row "Damaged pallet | <LPN>: <reason>" at the end of Delivery Details (Excel, the basic `.xls` and the PDF). Importing an exported log (Saved deliveries) puts the notes back on their pallets. The copy of the log in a Manifest check export doesn't include damage notes.

**Keyboard:** with the LPN box open, Tab goes to the damage choices, or to the Description box when there is one (since descriptions on any pallet went live with `main` `38c031c`, every tapped pallet has one while `palletDesc` is on, so the order is LPN box, Description, damage choices, Refused, Copy LPN) (Shift+Tab from **None**, or from the Description box, goes back to the LPN box). Leaving both the box and the choices (for example Tab past **Save**) closes them and keeps any change; when the keyboard was used, or focus would otherwise be lost because the table was redrawn, it goes back to that pallet's LPN. Since build 64 this also happens when Tab past the last choice lands on another control in that pallet's row before the table is redrawn (a slow phone or browser), so focus never ends up somewhere unexpected. On phones the row scrolls into view above the entry bar, even for the last pallet. The buttons are at least 44px tall.

Short pallets and torn wrap are not choices: the user asked for them to be taken out (see [decisions](decisions.md#damage-notes-on-pallets-build-49)). Use **Other…** for anything else.

## Refused pallets (build 62)

For a pallet that came off the trailer but was sent back with the driver. Tap its LPN (or Tab to it and press Enter): after the damage choices there is a **Refused (sent back)** button (at least 44px tall). Screen readers hear "Mark <LPN> as refused, sent back with the driver".

- **Tapping it** marks the pallet and closes the row. The Undo bar says "Marked <LPN> as refused (sent back)", and **Undo** takes the mark off. A change to the LPN box, the description or the damage made in the same edit goes on the same Undo bar.
- **In the log** the pallet stays in the table, with "Refused: sent back" in bold in the warning colour under its LPN (it wraps between words, not inside them) and a bar in the warning colour on the left of the LPN cell. Its LPN button is read as "Edit LPN <LPN>, refused, sent back…".
- **Taking it off:** tap the LPN again; the button now says **Not refused** (with a border in the warning colour). Tapping it gives "<LPN> is no longer marked as refused".
- **Counts:** a refused pallet isn't counted as received. The totals above the log, the type counts and the FSDU count leave it out, and a **Refused** count is shown on its own. The "n of x expected" line, the entry-bar counter and the Manifest check still count it, because it came off the trailer: a refused pallet on the manifest is still **Matched**.
- **A pallet can be refused and damaged** at once; both marks show.
- **Saved** with the log, in saved deliveries and in backups. Marking or unmarking it after an export counts as a change ("Changed since it was exported…").
- **On exports** (Excel, the basic `.xls`, Email PDF and Print) the pallet is still listed with its type and FSDU. The Pallet Type table's **Total** leaves it out, a "Refused (not in total)" row comes after "FSDU (not in total)" (only when there are refused pallets), and Delivery Details gets a row "Refused pallet | <LPN>: sent back with the driver", before any "Damaged pallet" rows. Importing an exported log (Excel, CSV or an app-made PDF) puts the mark back on the pallet.
- **Elsewhere:** the Manifest check's copy of the log (made from the current log, a saved delivery or an app-made PDF log) counts the same way, with its own "Refused (not in total)" row. In **Saved deliveries** the "n pallets" heading of each delivery includes refused pallets (the panel's help says so), and the line under it ends ", refused n".

The button can be switched off for everyone in the site settings (`refused`): it is no longer offered, the Guide paragraph, the "and refused pallets" part of the totals sentence and the changelog bullet are left out, but a pallet already marked keeps its mark, still shows it and is still left out of the totals. Marked as in testing, the note "In testing: Marking pallets as refused may not always work yet…" shows under the button. With `damage` switched off and `refused` on, tapping an LPN still opens a row, with only the Refused button (and the Description box when the pallet has one).

## Pallets with no LPN (build 55)

For a pallet that arrives without an LPN label. Pick the type (and tick FSDU if needed) as usual, then tap **No LPN**. It sits with **Live scan**, **Scan by photo** and (since build 64) **Upload photo** (under **Scan** on a phone), and screen readers hear it as "Add a pallet with no LPN".

- **Numbering:** the pallet is logged as "No LPN 1", then "No LPN 2" and so on: the next number is one more than the highest "No LPN n" in the log, so a removed pallet's number isn't reused while a higher one is there. The "Added" note says, for example, "Added #3: No LPN 1 · FMCG · FSDU". The type and FSDU follow the same rules as any pallet (FSDU clears afterwards; the type stays unless "Keep the last pallet type" is off). No duplicate or LPN-shape warning is shown for it.
- **Numbers stay unique:** whenever the log is saved, a second pallet with the same "No LPN n" (for example one brought back by **Undo** after a new one took its number, or one from an imported log) is renumbered to the next free number. The first one in the log keeps its number.
- **While a warning is waiting** (Skip / Add anyway), **No LPN** doesn't add anything: the message says "Answer the check first (Skip or Add anyway), then add the pallet with no LPN." with the warning sound.
- **Description:** straight after it is logged, the pallet opens for editing with the cursor in a **Description** box (placeholder "Optional: wrap, labels, PO number", up to 60 characters; screen readers hear "Description for No LPN 1"). Type what identifies it and press **Enter** to save, or **Escape** to leave it without a description (the pallet stays logged). Since build 56, Enter or Escape in a box that opened by itself puts the cursor back in the LPN box, ready for the next pallet, and Escape with text typed in the box says "Description not saved for No LPN 1." Leaving the box also saves it. Spaces are tidied and an emptied box removes the description. The Undo bar says "Description saved for No LPN 1" (or "Description removed from …").
- **A scanner in the description box:** for a pallet that has no saved description yet, a handheld scanner reading the next pallet into the box isn't kept as a description: the edit closes and the code goes into the LPN box and through the normal add, so it is logged as the next pallet (with the usual checks and warnings). Since build 56 this is decided by typing speed, not by the code's shape: it only happens when the text is at least 6 characters, is one word (no spaces), has 4 digits in a row, and arrived at scanner speed (from the first character to Enter in under 35 ms per character plus 100 ms). Anything typed by hand stays as the description, even one that looks like an LPN, such as a PO number like PO12345678. A scanned code that isn't LPN-shaped (for example a 20-digit carton code) also goes to the LPN box, where the usual warning shows. Before build 56 the rule was one LPN-shaped value (1–3 letters and 8–12 digits), however it was typed.
- **The LPN turns up later:** tap the pallet. Its LPN box is empty, with the hint "LPN if found" (screen readers: "LPN for No LPN 1, if you find one"). Type the LPN and press Enter: the pallet becomes a normal pallet (counted against a loaded manifest as usual) and keeps its description. Leaving the box empty keeps it as No LPN.
- **One Undo per edit:** everything changed in one edit (description, damage choice, LPN) goes on one Undo bar, for example "Description saved for No LPN 1. Changed No LPN 1 to VLT004040265", and **Undo** puts all of it back.
- **Damage** works the same as on any pallet: with damage on, the damage choices show under the description box. With damage switched off in the site settings, the description box still opens for these pallets.
- **Any pallet with a description** (for example one whose real LPN was typed in later) shows the Description box when it is tapped, so the text can be changed or removed.
- **In the log** "No LPN n" is shown in italic in the normal text font (not the LPN font), and a description shows on its own line under the LPN in bold, in the normal text colour.
- **Saved** with the log, in saved deliveries and in backups. Changing a description after an export counts as a change ("Changed since it was exported…").
- **On exports** each description gets a row "Pallet description | <LPN>: <description>" at the end of Delivery Details, after any "Damaged pallet" rows (Excel, the basic `.xls` and the PDF). The pallet itself is listed as "No LPN n" with its type and FSDU. Importing an exported log (Excel, CSV or an app-made PDF) puts the descriptions back on their pallets.
- **With a manifest loaded** these pallets are not counted as "not on the manifest" and get no "⚠ NOT on manifest" note or warning sound. For the Manifest check results see [Manifest check](#manifest-check).

The button can be switched off for everyone in the site settings (`noLpn`); pallets already logged with no LPN stay in the log. Marked as in testing, the note ("In testing: Logging pallets with no LPN may not always work yet…") shows in the description row of a No LPN pallet. On screens 300px wide or less (for example 200% browser zoom) the scan option buttons wrap onto two lines instead of running off the screen.

On screens under 360px wide a long description shows at most two lines under the LPN (since build 56); tap the LPN to see all of it in the box. Exports always have the whole text.

## FPP pallet descriptions (build 56)

An FPP pallet usually carries one product, so when one is logged the app asks what is on it.

- **When the box opens:** straight after an FPP pallet is logged by typing the LPN, by a handheld scanner, with **Add anyway** after a warning, or with **Scan by photo** or **Upload photo** (build 64), the pallet opens for editing with the cursor in its **Description** box. The placeholder is "What’s on it, e.g. kitchen roll" (No LPN pallets keep "Optional: wrap, labels, PO number"); screen readers hear "Description for <LPN>". With damage on, the damage choices show under it as usual.
- **Not during Live scan:** the phone's keyboard would cover the camera, so the box doesn't open by itself while Live scan is running. Tap the LPN afterwards to add a description.
- **Filling it in is optional.** Type what is on it (up to 60 characters) and press **Enter** to save it, or press **Enter** on the empty box to leave it blank. Either way the cursor goes back to the LPN box, ready for the next pallet. **Escape** closes it without saving and also goes back to the LPN box; if something had been typed, the message says "Description not saved for <LPN>." Leaving the box another way (tapping elsewhere) saves what is in it.
- **Scanning the next pallet while the box is open** logs it as the next pallet, not as the description, by the same scanner-speed rule as No LPN pallets (see [the scanner rule](#pallets-with-no-lpn-build-55)). A PO number typed by hand stays as the description.
- **Later:** any FPP pallet shows the Description box when its LPN is tapped, including one whose type was changed to FPP in the table. Other pallet types don't get the box unless they already have a description (since `main` `38c031c` they do, while `palletDesc` is on: see [Descriptions on any pallet](#descriptions-on-any-pallet-palletdesc)).
- **Screen readers:** a box that opened by itself is described as, for example, "Added #1: VLT004040265 · FPP. Optional: type what’s on it, or press Enter to skip and scan the next one." (No LPN pallets: "…Optional: describe the pallet, or press Enter…"), because moving the cursor can cut off the "Added" message. A box opened by tapping has no such hint. When the feature is marked as in testing, the testing note is read out with the box too.
- **The "Added" note** at the bottom of the screen doesn't cover the open box or its damage choices: the page scrolls them clear, and if it can't scroll far enough the note goes early (a warning note stays).
- **Shown, saved and exported** like any description: on its own line under the LPN, saved with the log, saved deliveries and backups, as "Pallet description | <LPN>: <description>" in Delivery Details on the Excel, basic `.xls` and PDF exports, and put back by importing an exported log.

It can be switched off for everyone in the site settings (`fppDesc`): the box then doesn't open by itself and isn't offered when an FPP pallet is tapped (an FPP pallet that already has a description still shows it), and the Guide paragraph and changelog bullet are left out. Marked as in testing, the note "In testing: Descriptions for FPP pallets may not always work yet…" shows in the description row of an FPP pallet. On a 320px screen, also with Extra large text and the testing note, the open box fits the screen without the page sliding sideways; the testing note wraps.

## Descriptions on any pallet (`palletDesc`)

Live since `main` `38c031c` (commits `073db40`..`17a595e`, still build 66), and in the Android app from Android APK build 2 (built from run 65), any pallet can have a description, not only FPP pallets and pallets with no LPN.

- **How:** tap the LPN of any pallet (BB, FMCG, FPP or Mixed). The row that opens under it starts with a **Description** box (up to 60 characters), then the damage choices, **Refused (sent back)** and **Copy LPN** as before. Type, for example, what is on it, the labels or a PO number, and press **Enter** or tap somewhere else to save it. The placeholder for BB, FMCG and Mixed pallets is "Optional: contents, labels, PO"; FPP pallets keep "What’s on it, e.g. kitchen roll" and No LPN pallets "Optional: wrap, labels, PO number".
- **The cursor stays in the LPN box** when a pallet is tapped; the box doesn't open by itself. It still only opens by itself (with the cursor in it) straight after logging an FPP pallet (`fppDesc`) or a pallet with **No LPN** (`noLpn`).
- **Keyboard:** from the LPN box, Tab goes to the Description box, then the damage choices, then **Refused (sent back)**, then **Copy LPN**.
- **Shown, saved, undone and exported** like any description: on its own line under the LPN, saved with the log, saved deliveries and backups; the Undo bar says "Description saved for <LPN>" and **Undo** takes it back; on the Excel, basic `.xls` and PDF exports as "Pallet description | <LPN>: <description>" in Delivery Details, whatever the pallet's type, and put back by importing an exported log.
- **On small phones:** the taller editor row no longer pushes the tapped pallet's LPN up under the table's column header (for example a 320px phone with Extra large text); the page scrolls back so the LPN stays below the header. The row is also scrolled clear of the "Added" note and the Undo bar as far as that allows; if the "Added" note still covers it, the note goes early (a warning stays).
- **Tapping the row's words** (the "In testing" note, the "Damage:" label) no longer closes the edit; the boxes and buttons in the row work as usual.

Switched off in the site settings (`palletDesc`), tapping a BB, FMCG or Mixed pallet gives no Description box (unless it already has a description), while FPP pallets (with `fppDesc` on) and No LPN pallets still get it. The Guide sentence "or add a description", its **Description on any pallet:** paragraph and the changelog bullet are left out. Marked as in testing, the note "In testing: Descriptions on any pallet may not always work yet…" shows in the description row of a tapped pallet (for an FPP pallet only when `fppDesc` isn't itself marked as in testing).

## Scanning

| Method | When to use |
|---|---|
| Live scan | Camera continuously adds each barcode it sees; the screen stays awake while it runs |
| Scan by photo | Fallback when live scanning is unreliable. Since build 64 it opens the camera to take a photo and reads the barcode; since build 65, when there is none, **Read the printed LPN** reads the same photo's printed number (see below) |
| Upload photo | Since build 64. Choose a photo of the label already on the phone (or take a new one), or since build 65 several photos at once; reads the barcode, and if there is none the LPN printed on the label is read instead and shown to check first (see below) |
| Hardware scanner | Focus the LPN box; the scanner types and presses Enter. Check a scanner first with **Settings → Test a handheld scanner** (build 59, see below). Since build 62 the screen stays on while the app is open, so scans aren't lost to a screen that has gone off (see below) |

"Ask me to confirm each scanned barcode" in Settings shows each scan for approval first.

**Scan by photo and Upload photo (build 64).** Since build 64 these are two buttons in the scan row (under **Scan** on a phone): **Live scan**, **Scan by photo**, **Upload photo** and **No LPN**. Either photo button stops Live scan first if it is running. The line under the camera box says "Reading barcode…" while the barcode is looked for (since build 64 it is set a moment after the camera box shows, so screen readers announce it).

- **Scan by photo** asks the phone for the back camera, so it opens the camera straight away (as before build 63). It reads the barcode. With no barcode, when **Upload photo** and reading **photos** are both switched on, it says "No barcode found. Try again closer and steadier, or use Read the printed LPN to read the number printed on the label in this photo." and shows a **Read the printed LPN** button in the camera box, next to **Stop scanning** (build 65; see below). Otherwise it says "No barcode found. Move closer, hold steady and try again." It never reads the label's printed text unless that button is tapped. (In build 64 it said "If the barcode is damaged, use Upload photo: it can read the LPN printed on the label." instead.)
- **Upload photo** opens the phone's picker without asking for the camera, so a photo already taken can be chosen; most phones also offer to take a new one there. Since build 65 several photos can be chosen at once (see "Several photos" below). It reads the barcode the same way, then, when there is none, reads the printed LPN as described below. (In build 63 this was what **Scan by photo** did, with the picker no longer forced to the camera.)
- **A check already waiting** (since build 65): if the check bar (Add or Skip) is showing when a photo's barcode is read, the barcode isn't added or asked about: "Answer the check above first (Add or Skip), then try the photo again."
- **The tip** under the buttons names only the photo buttons that are switched on: "Tip: if Live scan doesn’t work, try Scan by photo or Upload photo instead." (or just one of them). With Live scan switched off, or both photo buttons off, there is no tip.

**Read the printed LPN (build 65).** After **Scan by photo** finds no barcode, tap **Read the printed LPN** in the camera box to read the LPN printed on the label from that same photo, so it doesn't need to be taken again. It works exactly as the printed LPN reading below, except the first line says "Reading the LPN printed on the label. This can take up to a minute…". The button hides once tapped (focus moves to **Stop scanning** first, and then to **Skip** on the check that appears), and it goes when the camera box closes, Live scan starts or another photo is taken. If a check is already waiting, it says "Answer the check above first (Add or Skip), then use Read the printed LPN." and keeps the button and the photo, so tap it again after answering. It needs both **Upload photo** and reading **photos** switched on (`photoUpload` and `manifestPhotos`); without either the button never shows.

**Upload photo and the printed LPN (build 63, on Upload photo since build 64).** When no barcode can be read from an uploaded photo, and both **Upload photo** and reading **photos** are switched on in the site settings (`photoUpload` and `manifestPhotos`; in build 63 it was `scanByPhoto` and `manifestPhotos`), the app reads the LPN printed on the label with the same photo reader as the Manifest check's manifest photos. The Guide notes that this needs iOS 16 or newer on an iPhone:

- The line says "No barcode found, so reading the LPN printed on the label. This can take up to a minute…", followed by the reader's own progress (for example "Reading the printed LPN: No numbers found, so turning the photo to try again…"). The first use downloads the photo reader, as for manifest photos.
- **Never added straight away.** Printed text can be misread, so the reading always appears in the check bar with **Skip** and **Add**, even when "Ask me to confirm each scanned barcode" is off: "Read <LPN> from the printed label (no barcode found): check it matches the label. Add it as <type>?" Check it against the label, then tap **Add** (it is logged with the type and FSDU tick that were set when the check appeared) or **Skip**. The line under the camera box says "Read <LPN> from the printed label. Check it, then Add or Skip above."
- **Notes in the check bar:** ", one character corrected" is added inside the brackets when the photo reader corrected the number; "Its prefix isn’t in your prefix list." is added when a prefix list is set in the Manifest check, the LPN's prefix isn't on it and (since build 65) the usual LPN checks are off ("Warn me about duplicate or unusual LPNs before adding them" unticked in Settings). The LPN is still offered, because it is one pallet's own label. With the usual LPN checks on, any problem (already logged, prefix, digit count) is listed after it as for a typed LPN, and the button says **Add anyway**; build 64 also added the prefix note then, so the prefix was mentioned twice.
- **Which LPN is offered:** only readings shaped like an LPN (letters followed by 9 or 10 digits, or IM followed by 10 or 11) are offered, one at a time; one whose prefix is on the prefix list comes first. The same LPN printed twice on the label is offered once. Other LPNs read from the photo are named after it, up to three: "Other LPNs on the photo: … (scan them separately if they’re other pallets)." (with "…" after the third when there are more)
- **Other numbers** (order or PO numbers and the like) are never offered; they are only counted: "1 other number on the label was left out." or "n other numbers on the label were left out."
- **A number read without its letters** after "LPN:" on the label, with no LPN found: "No barcode found. A number after “LPN:” was read without its letters (<digits>): type it in with the letters at the start."
- **Nothing found:** "No barcode or LPN found. Try a clearer, closer photo of the label." (build 63 said "Move closer, hold steady and try again.")
- **Reader problems** are shown as they are, for example "The photo reader couldn’t load. Check you’re online and try again, or type the numbers in the box instead. (Reading photos needs iOS 16 or newer on an iPhone.)" when offline before the reader has been downloaded.
- **A check already waiting:** if the check bar is already showing, the photo isn't read: "Answer the check above first (Add or Skip), then try the photo again." If one appears while the photo is being read: "Read <LPN> from the printed label, but another check is waiting above. Answer it, then try the photo again."
- With **photos** switched off in the site settings, an uploaded photo with no barcode just says "No barcode found. Try a clearer, closer photo of the barcode."
- The problem report gets a `scan` entry starting "Printed LPN read:" (build 64: "Upload photo:"; build 63: "Scan by photo:") listing the LPNs read from the label (or "none") and how many other numbers were read.

**Several photos (Upload photo, build 65).** Choosing more than one photo reads them one after another:

- Every line under the camera box, and the question in the check bar, starts "Photo n of m: ", for example "Photo 2 of 5: Reading barcode…" or "Photo 3 of 5: Read <LPN> from the printed label (no barcode found): check it matches the label. Add it as <type>?"
- When a photo needs an answer (the printed LPN, a warning, or "Ask me to confirm each scanned barcode"), the next photo waits until **Add** or **Skip** is tapped. If a check from something else (for example a handheld scan) is already showing, the photos wait for it to be answered first; a photo whose reading finished while such a check was open is read again afterwards and then offered.
- While photos are being read, **Live scan**, **Scan by photo** and **Upload photo** don't start anything; they say "Still reading your photos. Answer the check above (Add or Skip) to go on to the next one." (when a check is waiting) or "Still reading your photos. Wait for them to finish before choosing more."
- At the end a summary says what happened, for example "5 photos read: 3 pallets added, 1 skipped, nothing found on 1 photo." ("no pallets added" or "1 pallet added" as needed; the skipped and nothing-found parts only when there are any). Notes that would otherwise be lost follow it: "Photo 2: a number after “LPN:” was read without its letters (<digits>): type it in with the letters at the start." and "Photo 4: couldn’t be read: <reason>." Only pallets from the photos are counted, not ones scanned or typed meanwhile. It shows under the camera box, or in the message line under the buttons if the camera box has closed.
- **What stops it:** **Stop scanning**, **Clear all**, **Start new delivery** (only once it really starts a new one, not the first press that only asks you to export first), opening or exporting a saved delivery, and unticking "Warn me about duplicate or unusual LPNs before adding them" in Settings. The photo buttons work again straight away, and the summary starts "Stopped reading photos (2 of 5 read): …" (or "Stopped reading photos because the log changed (2 of 5 read): …" after Clear all, Start new delivery or opening a saved delivery; that one isn't shown when the camera box has already closed). A question from the photos is taken away, but one from a handheld scan stays for an answer. A photo still being read when it stopped adds nothing and asks nothing, so no photo goes into the wrong delivery.
- Choosing one photo works as before, with no "Photo 1 of 1" and no summary.

On phones the four buttons share one row and stay at least 48px tall; labels can wrap onto two lines (line height 1.15, smaller side padding since build 64), and under 360px wide the gaps, padding and text are a little smaller still. Under 300px the row wraps. Since build 65 the camera box's own buttons (**Read the printed LPN**, **Torch**, **Stop scanning**) also wrap onto more lines, lined up on the right, on small phones and with big text, and the message beside them keeps at least 200px.

**Test a handheld scanner (build 59).** A section in Settings, after **Date format** and before **Share this app**: "Tap the box and scan any barcode with your handheld or Bluetooth scanner. Nothing is added to the log." The box is labelled **Scan a barcode here**. Nothing scanned into it is logged, and the box empties after each result, so the next barcode can be scanned straight away. It has no site switch, so it is always shown. The result line starts "Read “<code>” (<n> characters, in <m> ms)." (no time for a single character; the time runs from the first to the last character), then says what came after the code:

- **Enter:** "Enter was sent after it, so a scan into the LPN box logs the pallet straight away."
- **Tab:** "Tab was sent after it instead of Enter, so a scan into the LPN box would move to the next box without logging the pallet. Set the scanner to send Enter after each scan (often called a suffix or CR) using the setup barcodes in its manual." The cursor stays in the test box.
- **Nothing:** when no key comes for 1.5 seconds after the last character, "Nothing was sent after it, so you’d need to tap Add after each scan." and the same advice to set the scanner to send Enter. (Waiting 1.5 seconds means slow typing isn't cut off.)
- **Only Enter** with an empty box: "Only Enter came through. Scan a barcode with the box selected."

Then, for a code of 6 or more characters that took at least 35 ms per character plus 100 ms (the same speed rule the Description box uses to tell a scan from typing), it adds "It arrived at typing speed, so if that was the scanner it works, but some scanners can be set to send faster." Shorter codes never get this note. Last, it checks the code with the log's own LPN checks, leaving out "already logged" (so an LPN already in the log is still called an LPN):

- No problem: "It looks like an LPN."
- Only its prefix isn't in the prefix list (**Prefix presets** in the Manifest check): "It looks like an LPN, but its prefix RUN isn’t in your prefix list (add it under Prefix presets if it is one of yours)."
- Any other problem: "This barcode <problem>: try an LPN label to check.", for example "This barcode has 5 digits (usually 9 or 10): try an LPN label to check." or "This barcode doesn’t look like an LPN (1 to 3 letters then digits): try an LPN label to check." When there are several, they are joined with ", and "; a prefix problem is not mentioned alongside them.

**Keep the screen on (build 62).** **Settings → Keep the screen on while the app is open** (after the Vibrate tick box, ticked by default). A handheld scanner's scan is lost while the phone's screen is off, so while the app is open and on screen the app asks the browser to keep the screen on. The note under the tick box says: "So a handheld scanner’s scans aren’t lost while the screen is off. The phone won’t lock by itself while the app is open, so lock it before putting it in a pocket. It uses a little more battery, and stops when you switch to another app."

- The browser lets go of it whenever the app is hidden (another app, the home screen, the phone locked); the app asks again when it comes back on screen, and on the first tap if asking at start was refused.
- Unticking it lets the screen go off as normal straight away. **Live scan** still keeps the screen on while the camera is running, as it did before build 62, whatever the setting.
- Phones and browsers that don't let a web page keep the screen on simply ignore it; nothing is shown.
- The setting is saved on the phone with the other settings (and in backups). It has no site switch.

**Live scan on phones (build 41).** The camera view is at most `clamp(110px, 24vh, 200px)` tall, so on short phones the "Added: LPN (type)" line and **Stop scanning** stay on screen while scanning (checked at 360×640, 375×667 and 390×844). A warning about a scanned LPN (Skip / Add anyway) appears above the camera view, and the line under the camera says "Check the warning above." (it said "Check the message below." before build 41). Live scan messages are announced by screen readers. The "Added" confirmation note at the bottom of the screen can't block taps on the buttons under it.

**Torch (build 48).** A **Torch** button appears next to **Stop scanning** once the camera has started, but only when the phone lets a web page switch its light on (most Android phones; most iPhones don't, so there is no button there). Tap it to turn the light on, and again to turn it off; while it is on the button is filled in the accent colour and screen readers hear it as pressed. **Stop scanning** turns the light off and hides the button, and the next Live scan starts with it off. If the light can't be switched, the line under the camera says "The torch couldn't be switched on. Try more light, or Scan by photo." (since build 64 it names Scan by photo, or Upload photo when only that is switched on, or neither: "Try more light.") (or, when switching off, "The torch couldn't be switched off. Stop scanning to turn it off."), and the problem report gets a `scan` entry. When the button shows, the camera view on phones is a little shorter (at most `clamp(84px, 17vh, 200px)`) so the "Added" line, **Torch** and **Stop scanning** stay on screen, including with Extra large text on 360×640 and 375×667 screens.

**Scanning from further away (build 54).** Live scan asks the camera for a sharper picture than before (up to 1920×1080 where the phone uses its own barcode reader, which is most Android phones; up to 1280×720 on iPhones and Firefox, which use the slower built-in fallback reader) and asks it to keep focusing. A phone that can't give that uses the nearest it has. The Guide says: "To scan from further away, tap **+** in the corner of the camera picture to zoom in (on phones that allow it)."

- **Zoom buttons:** on phones that let a web page zoom the camera (most Android phones; most iPhones don't, so nothing shows there), a dark box with **−**, the current zoom (for example `2×`) and **+** appears in the top-right corner of the camera picture once the camera has started. It covers only that corner and doesn't make the camera box taller. Each button is at least 44×44px.
- **Steps:** **+** goes 1×, 1.5×, 2×, 3×, 4×, 5×, and **−** back down, never past what the camera can do (and never past 5×). **−** is greyed out at the lowest zoom and **+** at the highest. Screen readers hear the buttons as "Zoom out" and "Zoom in" in a group called "Zoom", and the new zoom level is announced.
- **Remembered:** the last zoom used is kept on this phone and used again the next time Live scan starts (if the camera allows it).
- **With the torch:** zooming keeps the torch on, and switching the torch keeps the zoom.
- Zoom has no switch of its own in the site settings: it comes and goes with Live scan (`liveScan`), and switching off `torch` doesn't affect it.

## Seal check (build 48)

When both **Seal in** and **Seal out** have something in them, the app compares them after removing spaces and anything that isn't a letter or digit, ignoring upper/lower case:

- the same number in both: "Seal in and seal out are the same number. Check them: the seal put on should be a new one."
- different lengths: "Seal in has 8 characters and seal out has 9. Check neither is mistyped." (with the real counts)

The note shows under the seal boxes when you leave a seal box (and whenever the delivery fields are filled in by the app: opening the app, loading a saved delivery or an imported log, or **Undo** after **Start new delivery**; starting a new delivery clears it). While you are typing, a note that no longer fits goes away, but a new one waits until you leave the box, so it doesn't flash up half-way through a number. It is only a reminder: it doesn't stop anything, the note itself isn't saved, and it doesn't appear on exports. Screen readers announce it.

## Clear trailer, seals and notes (build 53)

A **Clear trailer, seals and notes** button sits under **Delivery notes**. It is for the next trailer on the same day:

- It empties **Trailer number**, **Seal in**, **Seal out** and **Delivery notes**, and keeps **Date**, **Received**, **Expected pallets** and the pallets in the log.
- The change is saved straight away, any seal note goes, and the Undo bar says "Cleared the trailer, seals and notes"; **Undo** puts all four back (and saves them).
- The cursor moves to the **Trailer number** box, ready for the next one.
- The button is greyed out (and does nothing) while all four boxes are empty or only hold spaces; typing in any of them turns it on. It is at least 44px tall and fits the screen at 360px.

It doesn't start a new delivery: use **Start new delivery** to save the log and clear the pallets.

Since build 62 the clear can only be undone until the log or the delivery details change (see below).

## Undo for the last 10 changes (build 62)

Every change that offers Undo (removing a pallet with ✕ or ↶, an edit of a pallet, Clear all, Clear trailer, seals and notes, and Start new delivery) is kept in a list of the last 10, newest first. Older ones drop off. The list is only kept while the app is open: reloading the app forgets it.

- **The Undo bar** shows the newest, for example "Removed VLT000000003 (1 earlier)". Its **Undo** undoes that one, and the bar then shows the next.
- **The Undo button next to Export** shows while there is anything to undo, also after the bar has gone. It undoes the newest change each time. Screen readers hear, for example, "Undo: Removed VLT000000001 (2 earlier changes can be undone after it)". On phones it sits above Export, with **Clear all** below them at the bottom; on wider screens it is just left of Export, with Clear all on the left.
- **Ctrl+Z** (Cmd+Z on a Mac) undoes the newest change, but not while the cursor is in a box (there it undoes the typing, as usual), and not while the Guide, Settings, Saved deliveries, the install box or the report box is open over the log.
- **What was undone** is said in the status line under the log, for example "Undone: Removed VLT000000003. 1 more can be undone."
- **Keyboard focus:** when the last undo hides the bar and the Undo button while one of them had focus, focus moves to **Export**.
- **Whole-log changes:** **Clear all**, **Start new delivery** and **Clear trailer, seals and notes** can only be undone while the log and the delivery details are exactly as they were straight after the change. Once a pallet has been logged, or a box such as the trailer number has been changed, Undo says, for example, "“Cleared 1 pallet” can’t be undone now, because the log has changed since, and nor can the 1 earlier change." and the whole list is forgotten, because putting back the old log would lose the new work, and the older changes belonged to the old log. Other changes (a removed pallet, an edit) are undone whenever they are reached.
- **Forgotten on purpose:** opening a saved delivery, and restoring a backup, forget the whole list, since undoing would then change the wrong delivery or write old data over the restored backup.
- Nothing is undone while a saved delivery is being exported from Saved deliveries.
- Clear all now says "Cleared 1 pallet" for one (it said "Cleared 1 pallets" before build 62).

Deleting a saved delivery in Saved deliveries has its own "Deleted. Undo" in the list, as before; it isn't part of this list.

## Reminder about a delivery not exported (build 62)

When the app opens with a delivery in the log that has pallets, is dated before today, and hasn't been exported or emailed since its last change, a card at the top of the page (above the Delivery card, with a border in the warning colour) says, for example, "The delivery from 10/11/2026 (2 pallets) hasn’t been exported or emailed yet." with:

- **Export now:** closes the card, scrolls to **Export**, puts focus on it and opens the Export menu.

## Manifest check

The section opens (tap **Manifest check**) on **Manifest date**, then the two steps side by side: **1. LPN log** and **2. Manifest photos or PDFs** ("2. Manifest PDFs" when photo reading is switched off in the site settings, build 53). Below them is the closed **Prefix presets** section; its heading shows the current choice in brackets, for example "(all prefixes)", the preset name, or the typed prefix list. The **Manifest check** heading button and **Show missing** are at least 44px tall.

**Manifest date (still build 66, live since `main` `38c031c`).** Each time the app opens, **Manifest date** starts as today's date on the phone's clock. It can still be changed for this comparison, but the change isn't kept: the next time the app opens it is today again. Before that release, the site (build 66 on `main` until `38c031c`) and older builds instead remembered the last date picked on the phone (the `lpncmpdate` key), and fall back to today only when none was saved; the new code deletes that remembered date when it loads. The Changelog's v4.0 list gains the line "The Manifest check’s date now starts as today’s date each time the app opens."

On phones, while the Manifest check is open and its top is in the upper part of the screen (above 45% of the screen height), the pallet entry bar slides down out of view so it does not cover the section. It slides back when you scroll up towards the log, and it never slides away while you are typing or scanning into it.

- **Manifest sources:** photos (OCR), PDFs (text read exactly, scanned pages by OCR, several at once), or typed/pasted numbers. The PDF reader is downloaded the first time a PDF is read, so that needs internet once; after that PDFs can be read offline.
- **Take manifest photo and Upload manifest photos (commit `20083f2`, live since `main` `b650471`, 25 Nov 2026, still build 66; in the Android app from Android APK build 4).** Step 2 has three buttons: **Take manifest photo**, **Upload manifest photos** and **Add manifest PDFs**. **Take manifest photo** opens the camera straight away to photograph one manifest page; each tap takes one photo, which is read exactly like an uploaded one (the same note, prefix list, "Add … to the prefix list" button and **Report a problem with these photos** link). Tap it again for the next page. On the website it only shows on touch screens (phones and tablets); on a computer only **Upload manifest photos** is there. In the Android app it always shows (since commit `222e0f3`), because Android's web view doesn't always say it is a touch screen. **Upload manifest photos** (called **Add manifest photo** before this commit) picks one or more photos already taken. Both are hidden when reading photos is switched off in the site settings (`manifestPhotos`). In the Android app the camera opens through the phone's camera app, as for **Scan by photo**.
- **Live read manifest and Live read log (Android app only, from Android APK build 4).** In the app, step 2 also has **Live read manifest** and step 1 **Live read log**: the camera reads the printed page as you move the phone down it and adds each LPN to the manifest numbers or the log numbers once it has been read clearly twice. See [Android app](#android-app-offline-apk).
- **Log sources:** Use current log, a saved delivery, an exported `.xlsx`/`.csv`/`.xls`, an app-made PDF (read exactly), another PDF, or a photo of a printed log.
- **Use n as expected:** while a manifest is loaded and Expected pallets is empty, the progress line offers to copy the manifest count into Expected pallets.
- **How photos are read (build 35):** each photo is made black and white by comparing every point with the paper around it, so shade across the page and paper grain don't turn into junk, and pages with ruled lines are read in full. The numbers on one photo are then matched to each other: when most of a page's numbers are, say, `VLT` + 9 digits, a reading such as `VL1004040355` is put back to `VLT004040355`, and an O read as an extra 0 after the prefix (`RUN0001832816` where the others are `RUN001832…`) is dropped. A number with nothing to compare against is kept as read. Since build 36, specks on the paper that read as a code are left out: when a photo's numbers show a clear pattern, a reading with a prefix seen nowhere else on that photo and without an LPN's digit count (9 or 10, or 10 or 11 for `IM`; for example `DFA51400180` on a page of `VLT` numbers) is not added, and the problem log notes it as "Ignored as not looking like this page's LPNs". A short reading of a prefix the page uses is still added so you can check it. Since build 37, a reading whose prefix has a different number of letters from every prefix on the photo (for example `CO1080002090` or `L1121100001` among `VLT` numbers) is left out too. A number with another prefix of the same length and 9 or 10 digits is still added. `IM` numbers (full pallet picks, two letters) are always kept, whatever the other numbers look like. When the most common number shape on a photo is a tie (for example 9 and 10 digits), the plainly printed readings decide it.
- **Prefix presets** (tap the heading to open) limit which numbers OCR picks up. Since build 53, when photo reading is switched off in the site settings, the presets are hidden and any saved prefix list is ignored, so PDFs give every number. The list is applied after the tidy-up above, so a mended number with a listed prefix is kept. Leave the list empty for any 1–3 letter prefix. Presets come from `presets.json` and from presets saved on the device.
- **What each file added:** after reading manifest photos, manifest PDFs or log photos, the message has one note per file, for example "Photo 1: found 2 LPNs, 1 new, 1 already in the list." (PDFs are named by their file name, log photos as "Log photo n"). A file where nothing was found says "No LPNs could be read: try a closer, sharper photo in good light." or, for a PDF, "No LPNs could be read from this PDF."
- **Numbers left out by the prefix list:** when a prefix list is set, numbers of 1–3 letters followed by an LPN's digit count (exactly 9 or 10 real digits, or 10 or 11 after `IM`; since build 40 also an `IM` number with 9 digits, one short and probably a misread) whose letters aren't in the list are not added, but the note names them (up to four, then "…"), for example "2 other numbers (QUB001899186, QUB001899210) start with QUB, which isn’t in the prefix list. If they are LPNs, add QUB under Prefix presets (or clear the prefixes) and read the photo again." For PDFs it says "read the PDF again". Numbers of other lengths (PO, phone or reference numbers, such as `TEL 01234567890`) are never named. With an empty prefix list nothing is left out.
- **Readings that didn't look like the page (build 37):** readings left out by the tidy-up that have an LPN's digit count (9 or 10, or 10 or 11 for `IM`) are named in the photo's note, for example "3 other readings (CO1080002090, RR1004040021, L1121100001) didn’t look like the other LPNs on this page, so they were left out. If one is a real LPN, type it in the box." They are not added; type in any that are real.
- **Numbers corrected to match the page (build 45):** when the tidy-up changes a reading to match the other numbers on the photo (for example `VL1004040355` to `VLT004040355`, or an extra 0 dropped), and the corrected number is added, the photo's note names it so it can be checked. Since build 59 it reads "1 number looked misread, so it was corrected (VLT004040355): check it against the paper." (or "n numbers looked misread, so they were corrected (…): check them against the paper.", up to four named, then "…"); before build 59 it said "corrected to match the others on the page", which was wrong for a page with one LPN, where nothing is matched to other numbers. A number read twice and corrected is named once. The problem log adds "corrected to match the page" with the numbers.
- **Single-letter prefixes, numbers read with a gap and pages with one LPN (build 57, from problem report #2):** an LPN that starts with a single `V`, `R` or `Q` (for example `V0013323651` on a page of `VLT` numbers) is now kept when it has an LPN's digit count (9 or 10) and was printed straight after an "LPN:" label; before, its one-letter prefix among three-letter ones got it left out. Without the label in front, or with the wrong number of digits (`V12345`, or a speck read as `R014908200`), it is still left out. A number read with a gap in it straight after an "LPN:" label (`QUB00191 1625`) is joined into one LPN (`QUB001911625`) when the two parts sit on the same line close together and together have an LPN's digit count; digits further along the line, on the next line or without a label in front are never joined on. The word "LPN" is never taken as a prefix (`LPN 0013323651` doesn't become an LPN). On a photo with nothing to compare with (one LPN on it, for example), a close-up reading that only adds a 0 straight after the prefix to a number read plainly (`RUN0001840861` for a printed `RUN001840861`) is not used: the plain reading is kept and named for checking with the usual corrected-number sentence ("1 number looked misread, so it was corrected (RUN001840861): check it against the paper." since build 59). On such a page, a reading without an "LPN:" label whose prefix differs from the labelled ones (print showing through from the back of the page, such as `FI8111010009`) is left out and, with an LPN's digit count, named as "didn’t look like the other LPNs on this page"; a `V`, `R` or `Q` number with an LPN's digit count is never left out this way.
- **A number read without its letters (build 57):** when the reader sees 9 or 10 digits straight after an "LPN:" label but not the letters before them (the `V` of `V0013323651`), the number is not added, but the photo's note names it: "A number after “LPN:” (0013323651) was read without its letters: check the paper and type it in with the letters at the start." ("n numbers after “LPN:” (…) were read without their letters: … type them in …" for more, up to four named, then "…"). It comes after the corrected-number sentence and before the "didn’t look like" one. A photo with only such numbers counts as having found something, so it isn't turned and read again. The problem log records "Read after LPN: without its letters: <digits>".
- **Report a problem with these photos (build 45):** after a batch of manifest photos is read, a **Report a problem with these photos** link appears under the message. It opens the report box (see [Report a problem or idea](#report-a-problem-or-idea)) set to **Problem**, with the photo that read worst already attached (made smaller as usual): a photo that couldn't be read first, then the one with the fewest LPNs found, then the one with the most numbers skipped by the prefix list, left out or corrected. The text box stays empty; its hint asks "What went wrong with photo n? For example, which numbers were missing or wrong.", so the report always has your own words. While the photo is being added the note says "Adding photo n…" and **Send** is greyed out; then it says "Photo n attached (n KB)". If the photo can't be added, the box says so and the report can still be sent. The photos are only held in memory for this, never saved; **Clear** and reading manifest PDFs remove the link and forget them, and so does choosing a new batch.
- **Sideways and upside-down photos (builds 46 and 47):** when a manifest photo gives nothing that looks like an LPN (no LPNs, nothing left out by the prefix list and no readings that didn't look like the page), it is turned 90° and read again, and if that also finds nothing, turned 270° and read again. Since build 47, if neither sideways turn finds anything, it is turned 180° (upside down) and read once more. While this happens the message shows "Photo n of n: No numbers found, so turning the photo to try again…". When a turned reading finds something, the photo's note ends "The photo was sideways, so it was turned to read it." (90° or 270°) or "The photo was upside down, so it was turned to read it." (180°). If no way up finds anything, the usual "No LPNs could be read…" note shows; a blank or blurry photo is therefore read four times before that note, so it takes longer than an upright one. A photo that only has numbers with an unlisted prefix counts as found, so it is not turned. Log photos and scanned PDF pages go through the same reader and are turned the same way, but only manifest photos show the "turning the photo" message. After each photo the app frees the memory of its full-size copies straight away (phones, Safari above all, give it back late otherwise).
- **Add a prefix with one tap (build 46):** when manifest photos or manifest PDFs give numbers that were left out because their prefix isn't in the prefix list, the note says "…tap Add RBY below to add them to the prefix list." (instead of "add RBY under Prefix presets … and read the photo again"), and a button **Add RBY to the prefix list** appears under the message, one per missing prefix. Check them against the paper copy." followed by the earlier per-photo notes (with the "tap Add" sentence removed). If Check results is open, the results are worked out again. The button goes, and keyboard focus moves to the next Add button or, if none is left, the manifest numbers box. The buttons only show while a prefix list is set; they go when the prefix list is changed to include that prefix, or cleared, and with **Clear** or a new batch of photos or PDFs. Log photos don't get the button.
- **One bad file doesn't stop the rest:** if a manifest photo or log photo can't be read, its note says "Photo n: couldn’t be read (reason)." and the next photos are still read. Manifest PDFs already worked this way; a PDF that fails is listed under "Couldn’t read:". The exception is the PDF reader failing to load, which stops at that file with the "PDF reader couldn’t load" message.
- **Unusual digit counts:** after reading or typing manifest or log numbers, the message ends with "These have an unusual number of digits, so check them against the paper copy: …" (up to eight, then "and n more") for lines that are letters followed by digits but not 9 or 10 digits (10 or 11 for `IM`).  
  ```
  Manifest check 01/11/2026, trailer TR4471
  Missing from the log (2): RBY006292169, RBY006292211
  On the log only, to book in (1): RUN0001830999
  Matched: 2 of 4 on the manifest
  ```

  The date and trailer parts are left out when they aren't known, and an empty list says "none". When the numbers come from more than one DC, a "By DC: …" line follows "Matched" (see By DC above; with the three pallets in this example, from Rugby, Runcorn and Vault, the line is "By DC: Rugby: 2 missing; Runcorn: 1 extra, 1 matched; Vault: 1 matched"). When **Notes for this check** has text, the message ends with a last line "Notes: <the notes>" (see below). Closing the share menu without sending does nothing. Where there is no share menu (most computers), or sharing fails, the text is copied and the message under the buttons says "The missing list was copied. Paste it into a message or email." If copying isn't allowed either, the message shows the list itself ("Sharing isn’t available here. The list is: …").
- **Notes for this check (commit `9f144a4`, live since `main` `b4d5508`, 25 Nov 2026, still build 66; in the Android app from Android APK build 6).** Under the manifest numbers box is a two-line box **Notes for this check (optional)**, for anything worth recording about this comparison, such as a DC that didn't send a manifest (the placeholder reads "For example: one DC didn’t send a manifest"). It takes up to 500 characters. What you type is kept on this phone as you type, so it is still there after closing or reloading the app, until you tap **Clear** in the Manifest check (which empties it with the rest). **Start new delivery** does not empty it. The notes are kept in backups like the other saved data. When the notes have text they go:
  - on the **Excel** export, in the Delivery Details box on the right, under Date: a grey "Notes" heading row and a row with the text across both columns, made tall enough for the wrapped lines;
  - on the **Email PDF** and **Print** copy, as a "Notes" row in the Delivery Details table, under Date;
  - at the end of the **Share missing list** message, as "Notes: <the notes>".

  On the exports and the shared message, line breaks and runs of spaces in the notes become single spaces. Empty notes add nothing anywhere. The Guide's Manifest check section and the v4.0 Changelog describe it.
- **Export** gives the comparison as Excel (`Manifest-check-<date>-<trailer>.xlsx`), Email PDF or Print (`Manifest-check-<date>-<trailer>.pdf`). Since build 46 the trailer part is the trailer number of the delivery that was checked: the current log's trailer box when **Use current log** loaded it, or the saved delivery's trailer when a saved delivery was chosen. A log uploaded as a file or read from a photo gives no trailer part, and neither does a delivery without a trailer number. When the comparison is added to an uploaded `.xlsx` log, the file keeps the log's own name with " (with manifest check)". With "Include a copy of the log" on, an uploaded `.xlsx` log gets the comparison as a new tab, and PDFs get the log appended. When a log PDF is appended, any links and page-open actions in it are removed; the printed pages are unchanged. Values from an uploaded log are only ever written as plain text or numbers, so a file from outside can't add formulas or links to the export.
- **Photo reader:** reading photos downloads the photo reader and its language data the first time, which can take a while on a weak signal. If it hasn't started after 90 seconds, or can't be downloaded, it stops with "The photo reader couldn’t load…" and the next try downloads it again. Since build 41 one reader is started for a batch of photos (or scanned PDF pages) and reused, so the second and later photos start faster; it is closed 15 seconds after the last photo to free memory. If one photo takes longer than 2 minutes to read (for example the phone stopped the reader while the app was in the background), that photo fails with "The photo reader stopped. Try the photo again." and the next photo gets a fresh reader. Reading manifest photos and a log photo at the same time is fine: they take turns. Reading photos needs iOS 16 or newer on an iPhone; older phones can still scan barcodes, read PDFs (iOS 16.4+) and type numbers.

Print as many copies as needed. Nothing from the log goes on it, and it doesn't change the "Exported at" note. Where printing isn't available, the PDF is saved instead. Since build 66 opening the Export menu scrolls it so its last item isn't hidden behind the entry bar on a phone.

**Trailer number in file names (build 46).** The `-<trailer>` part is the Trailer number box, for example `LPN-log-2026-11-01-TR4471.xlsx`. Anything other than letters, numbers and dashes becomes a dash, repeated dashes become one, dashes at the start and end are dropped, and it is cut to 20 characters (`TR 4471/A` gives `-TR-4471-A`). **Site or store name in the title (build 62).** **Settings → Site or store name** (under Text size, placeholder "Optional, for example 323 Wigan", up to 40 characters; the note says "Added to the title of every export, so logs from different sites are easy to tell apart."). When set, it is added after the title of every export, for example "Goods-in pallet log – 323 Wigan" and "Manifest check – 323 Wigan": the Excel log, the basic `.xls`, the PDF (Email PDF and Print), exports from Saved deliveries, and the Manifest check's Excel and PDF. Runs of spaces become one and the ends are trimmed when it is saved. A long title gets a smaller font so it isn't cut off: on the Excel sheets titles over 34 characters shrink from 22pt (down to 13pt at the least), and on PDFs the font goes down from 18pt until the title fits between the margins (down to 11pt). Left blank (the default), the titles are as before. The name isn't in the file names. It is saved on the phone with the other settings (and in backups).

**Refused pallets on exports (build 62).** See [Refused pallets](#refused-pallets-build-62): left out of **Total**, counted in a "Refused (not in total)" row, and listed in Delivery Details as "Refused pallet | <LPN>: sent back with the driver". In the Excel log the Pallet Type box's thick border closes under the Refused row, and the Delivery Details box moves down one row.

**By DC on the pallet log exports (commits `c72e505` and `789d032`, live since `main` `14ac5a4`, 26 Nov 2026, still build 66; in the Android app from Android APK build 7, being built, not handed out yet).** When the log's pallets come from two or more DC groups, Delivery Details on the Excel log, the basic `.xls`, Email PDF and Print gets a "By DC" row straight after Expected pallets (or after Received by when Expected pallets is empty), for example "Rugby 3 · Vault 3 · Runcorn 1 · Other 1". The DC comes from each LPN's letters (Vault `VLT`/`V`, Runcorn `RUN`/`R`, Qube `QUB`/`Q`, Rugby `RBY`/`IM`); any other letters count as **Other**, and numbers with no letters aren't counted. DCs with the most pallets come first (equal counts by name), Other last. Refused pallets are counted (they count towards the expected pallets); No LPN pallets aren't. There is no row with only one group, or when no pallet is from one of the four DCs.

In the Android app, when **Expected per DC** is filled in, the row shows each DC against what was expected even with only one DC, for example "Vault 2 of 2 (all in) · Rugby 0 of 1", and "(n over)" when a DC has more than expected ("Vault 2 of 1 (1 over)"). Exports write "(all in)" rather than the ✓ used on the phone's screens, as the PDF font has no tick. The website has no Expected per DC boxes, so its exports never show "of n".

Importing an exported log (Saved deliveries or the Manifest check) ignores the By DC row: the pallets and the other delivery details are read as before.

If an expected count is set and differs from the total, the first export attempt shows a reminder instead; choosing it again proceeds.

**Long LPNs and notes in the spreadsheets.** On the pallet log and the manifest check sheet, the LPN column widens to fit the longest LPN in the file (it never gets narrower than the usual width, and stops at 40 characters wide). A value too long even for that, such as a web address scanned by mistake, wraps onto a taller row instead of stretching the column. Rows in the Delivery Details table grow tall enough to show long notes in full. The logo above the table is sized to the width of the table.

**Which version made the file.** Every export says which version of the app made it, for example "LPN Pallet Log v4.0 (build 52)". The version is the newest entry in the Changelog (its first heading, `v4.0` since build 52; `v3.30` before); the build is the cache number in `sw.js` (`lpn-log-v52` is build 52).

| Export | Where the version appears |
|---|---|
| Excel log and manifest check sheet | A small grey line under the tables: "Made with LPN Pallet Log v4.0 (build 52) on dd/mm/yyyy at hh:mm." (the date follows the Date format setting), and the left side of the printed page footer |
| PDF (Email PDF, Print, saved deliveries) | The left side of the page footer |

Importing an exported log (Saved deliveries or the Manifest check) stops reading LPNs at the "Made with" line, so it is never taken for a pallet, even if someone has deleted the blank row above it. Both read spreadsheets the same way, so a log gives the same pallets in either place.

## Share log (build 66)

**Share log** (switch `twoPhones`) is the button next to **Start new delivery** and **Saved deliveries** under the log. It opens the panel "Share the log with another person", for when two people unload one trailer: each scans on their own phone, then all the pallets go on one phone to export. Both phones need the latest version of the app.

1. **To send your pallets:** tap **Show my pallets as QR codes**. The phone shows its pallets as QR codes, with "Code 1 of n" under them and a line such as "31 pallets in 3 codes. Leave this open until the other phone says they’re added." With more than one code they change by themselves every 2 seconds and go round again. Keep the screen bright and steady. **Previous** and **Next** hold one code (for a slow camera); tap **Show my pallets as QR codes** to start the automatic change again. The codes are made from the pallets logged at that moment: if you log more, tap Show again. Closing the panel stops them. With no pallets it says "There are no pallets on this phone to send." Sending doesn't change this phone's log.
2. **To add another person’s pallets:** tap **Scan the other phone’s codes**. The panel closes and the camera starts, with "Point the camera at the other phone’s QR codes." The codes can be read in any order; each new one beeps and the line says "Codes from the other phone: k of n read. Keep the camera on its screen." When every code is in, the camera stops and the pallets are added after this log's, with their type, FSDU, damage, description and refused mark. The message says "Added n pallets from the other phone." and, if some were already here, "n were already in this log."

- Pallets already in the log (spaces and capitals ignored) aren't added twice. A "No LPN" pallet from the other phone gets this log's next number (so No LPN 1 there may become No LPN 3 here).
- One **Undo** ("Added n pallets from the other phone") takes away just those pallets; pallets logged since stay.
- If both phones have a trailer number and they differ, the message adds "Check the trailer: the other phone has …, this one has …."

**Delivery details go with the pallets** (commit `e6f6832` with fixes in `477182a`, live since `main` `b650471`, 25 Nov 2026, still build 66; in the Android app from Android APK build 4). Besides the trailer number, the codes carry the sending phone's **Expected pallets**, **Seal in**, **Seal out** and delivery **Notes** (only boxes with something in them; notes are cut at 500 characters). The panel's hint says so: "The trailer number, expected pallets, seals and delivery notes go with them. The other phone fills in any of its boxes that are empty, and asks before changing ones that are different. A phone with an older version of the app still adds the pallets, but not the delivery details."

- **Empty boxes are filled in.** Any of the trailer, expected pallets, seals or notes that is empty on the receiving phone takes the other phone's value and is saved, as if it had been typed. The message adds, for example, "Added from the other phone: trailer, expected pallets, delivery notes." and the Undo bar reads "Delivery details from the other phone"; **Undo** empties those boxes again.
- **Different boxes are asked about.** If expected pallets, a seal or the notes differ, a bar above the Undo bar says, for example, "The other phone has different delivery details: seal in 111111." (notes are named but not shown). **Use theirs** puts the other phone's values in ("Delivery details changed to the other phone’s.", and **Undo**: "Used the other phone’s delivery details"); **Keep mine** leaves them ("Kept this phone’s delivery details."). Capitals are ignored, and notes count as the same when one is the start of the other, so long notes cut to 500 characters aren't asked about.
- **The trailer is never asked about twice:** a different trailer only gets the "Check the trailer" line above, and keeps this phone's number.
- **The question belongs to this delivery:** **Start new delivery**, loading another delivery, or **Clear trailer, seals and notes** closes it, so Use theirs can't change the wrong delivery.
- **Older copies of the app** still add the pallets from the new codes and ignore the details; codes from an older copy add the pallets and change no delivery box.
- A QR code from another phone is never logged as a pallet. Seen during ordinary scanning, it says to use Share log, then Scan the other phone's codes. The same set of codes can't be added twice ("These pallets were already added from the other phone. On that phone, close the codes."); this is remembered until the app is reloaded.
- If a check is waiting (Add or Skip), the codes wait until it is answered.
- At most 500 pallets can be sent this way.
- Accented letters and symbols in descriptions and damage notes come through unchanged.

- Holds what was saved or imported this week and last week (weeks start on Sunday); older entries are removed automatically. Since build 61 the panel's help says "deliveries you saved or imported this week and last week are kept". Since build 60 a saved delivery is kept by the later of its delivery date and the day it was saved. So **Start new delivery** on a log dated three weeks ago saves it and it stays in Saved deliveries until the end of next week, like any delivery saved today; a delivery dated before last week and also saved before last week is still removed.

Since build 62 opening one forgets the log's undo list (see [Undo for the last 10 changes](#undo-for-the-last-10-changes-build-62)) and checks the reminder about a delivery not exported.

The panel's help adds "The number of pallets shown for each includes any refused ones." (left out when `refused` is switched off).

("Imported 1 pallet." for one, since build 61), plus a sentence when some pallet types couldn't be read and were set to Mixed. Before build 60 one dated before last week was removed at once and the panel offered **Load it into the log** instead; build 61 removed that message and button from the code.
- The panel shows when this device was last backed up, with **Back up now**.
- **Find an LPN (build 46):** a search box above the list ("Type or paste part of an LPN"). Type 3 or more letters or numbers from any part of an LPN; spaces, dashes and case are ignored (`4040 265` finds `VLT004040265`). Only the saved deliveries that hold a matching pallet stay in the list, and each shows a "Found:" line naming up to three matching pallets with their type, for example "Found: VLT004040265 (BB)", then "and n more". The line under the box says "Found in n saved deliveries." or "Not in any saved delivery from the last two weeks.", and adds "It is also in the current log." when the current log has a match. Undo") is never counted.

## Backup and restore

Everything (the current log, saved deliveries, names, presets, logo and settings) is stored in this browser only.

**Back up:** **Settings → Backup → Download backup**, or **Back up now** in Saved deliveries. This saves `lpn-backup-<yyyy-mm-dd>.json`.

**Restore** (for example on a new phone):

1. **Settings → Backup → Restore backup**, then choose the `.json` file.
2. The app checks the file and says what it holds, for example "This backup has a log of 12 pallets and 4 saved deliveries." Nothing has changed yet. A file that isn't a backup from this app, or is damaged, is refused here.
3. Tap **Replace my data with this backup**, or **Cancel** to leave everything as it is.
4. A copy of your current data downloads first (`lpn-backup-<date>.json`). On iPhone, confirm the download if asked. If the copy can't be saved, the restore stops and nothing is replaced.
5. The message says "Backup restored. Make sure the copy of your previous data has saved, then reload the app…". Check the copy has saved, then tap **Reload the app**. The app doesn't reload by itself. Since build 62 a restore forgets the undo list at once, so an Undo before the reload can't write the old data over the restored backup.

While checking, the app tidies the backup: anything it doesn't recognise is left out (for example an unknown pallet type becomes Mixed, and a logo that isn't a PNG or JPEG image is dropped). The same tidying happens every time the app starts, so damaged saved data can't stop it opening.

The problem log (see [Problem report](#problem-report)) is never put in a backup, is ignored if a backup file contains one, and is left as it was when a backup is restored.

## Report a problem or idea

Since build 44 the form is a box in the middle of the screen. Open it with the **Report a problem** button (speech-bubble icon) at the top of the page: at the right of the title row on phones, just before **Guide** on desktop. Since build 58 the button says **Report a problem** (it said just **Report** before), so it's clear it is for problems with the app or ideas for it; screen readers still hear "Report a problem or idea". On screens narrower than 480px the words go on two lines; narrower than 360px the icon is left out as well, so the app name keeps its room. **Settings → Report a problem or idea** and the Guide's **Report a problem or idea** link in section 9 open the same box on top of the panel, which stays open behind it. The cursor goes into the text box. **Close**, **Escape** or tapping outside the box closes it and puts you back where you were (in the Guide or Settings if you came from there).

1. Choose **Problem** or **Idea**.
2. Type what happened or what would help (up to 4000 characters).
3. Optional (build 50): **Your name (optional)**, up to 60 characters, so Jamie knows who to ask. Runs of spaces become one and the ends are trimmed. The name is remembered on this phone and filled in the next time the box opens; clearing the box and sending forgets it. Left empty, no name is sent.
4. Optional: **Add a photo**. It is made smaller before sending (at most 1600px along the long side, as a JPEG) and the note shows its size, for example "Photo added (240 KB)". **Change photo** and **Remove photo** appear once one is added.
5. **Attach the problem report** is ticked by default; untick it to send only the text and photo. The problem report holds the recent actions on this phone, with the LPNs involved (see [Problem report](#problem-report)).
6. Tap **Send**. "Sent. Thank you!" means it has arrived; the box closes by itself 1.5 seconds later.

Since build 50, **Send**, **Close** and the status line under them are pinned to the bottom of the box, so they stay on screen however tall the form gets (Extra large text, the name box, a short phone or the keyboard open); the form scrolls above them. On screens no taller than 700px the text box is a little shorter (at least 76px).

Reports go to Jamie's private GitHub repository through a Cloudflare server. A name, when given, shows in the issue under "From:" as plain text. Settings' **Report a problem or idea** section points to the Guide's **Your data and privacy** section for what a report includes (see [Your data and privacy](#your-data-and-privacy-build-50)). The problem report includes the LPNs and manifest numbers on the phone, file names, the start of text read from photos, and the browser and screen size. Since build 44 the box itself no longer says where reports go (the user's choice); it starts with "Tell Jamie what went wrong or what would help. With no signal, it’s kept on this phone and sent when you’re back online."

**Current setting:** switched off on the website since `main` `23b4714` (21 Nov 2026, `report: false` in `config.js`, commit `8474339`), and always off in the Android app. So at the moment no copy of the app sends reports: to tell Jamie about a problem, use **Settings → Problem report → Download problem report** and send the file by hand with a description of what happened (the app doesn't say how or to whom). Reports that were already waiting on a phone stay there and are not sent. The reporting server still runs and is still checked every week, so switching `report` back on is enough to bring the button back.

**Switched off (build 53).** With `report` set to `false` in the site settings, the **Report a problem** button, the box, the Settings section, the Guide link and **Report a problem with these photos** are all gone, and reports already waiting on the phone are not sent. Use **Download problem report** instead.

**Not set up yet.** The reporting server is online (since build 43). If the app's reporting address is ever empty, **Send** says "Reporting isn’t set up yet. Use Download problem report below and send the file to Jamie instead." (see [installation](installation.md#feedback-worker-report-a-problem-or-idea)).

**No signal.** If the phone is offline, or the server is busy, the report is kept on the phone and sent when it is back online (when the browser reports it is online, and 4 seconds after the app opens). The message says "No signal or the server is busy: saved on this phone, and it will be sent when you’re back online." Photos are not kept: the message then adds that the photo should be sent again when there is signal. At most 5 reports (about 300 KB in all) can wait; past that it says there's no room and suggests trying again with signal or using Download problem report. When the box opens with reports waiting, it says how many ("2 reports are waiting to be sent when you’re back online."). A report the server refuses (for example too long) shows the server's reason and is not kept. Waiting reports belong to the phone: they are never put in a backup or taken from one.

## Problem report

**Settings → Problem report** has **Download problem report** and **Clear**.

The app keeps a short log of what it has done on this device: the last 300 events, each cut to 300 characters. It records manifest photo, manifest PDF and log photo reads, the LPNs read from a label's printed text by **Upload photo** or **Read the printed LPN** (build 65; entries start "Printed LPN read:"; **Upload photo** only in build 64, **Scan by photo** in build 63) (file type and size, how many LPNs were found, added and already listed, numbers left out by the prefix list, readings left out as not looking like the page's LPNs, failures), what the photo reader and PDF reader got from each file (word or page count, LPNs found and the first 150 characters of the text read from a photo), backup restores, and script errors (including failed promises). It is only sent if you attach it to a report from **Report a problem or idea**; nothing is sent by itself.

**Download problem report** saves a plain text file, `lpn-problem-report-<yyyy-mm-dd>.txt`, with:

- when it was made, the app version and build, the browser (user agent), screen and window size and pixel ratio, whether it runs as an installed app, whether it is online and whether the service worker is active;
- the current state: pallets in the log, delivery date, expected pallets, the Manifest check prefixes, the manifest numbers and log numbers in the Manifest check boxes, and the Manifest check message;
- the recent events, oldest first, each with its time and kind (`manifest`, `pdf`, `ocr`, `backup`, `error`).

The message then says "Problem report downloaded. Send it along with what happened." **Clear** empties the problem log ("Problem log cleared.").

Section 9 of the Guide says: "Something not working, or an idea?" with a **Report a problem or idea** link (since build 42; before, it told staff to download the problem report and send it). With `report` off (the website since `main` `23b4714`, and the Android app) that line is left out, so only the text in **Settings → Problem report** ("If something goes wrong, download a problem report straight away and send it with a description of what happened.") tells staff about the file. The report contains LPNs, file names and text read from photos, so treat it like a delivery record.

## Android app (offline APK)

Since 19 Nov 2026 there is also an Android app: an APK made from the same files as the website, with every library and the photo reader inside it, so it works with no internet at all. Each push checks it, but a new APK is only built when the owner approves an Android update and runs the build by hand, so one APK carries several changes. It is built from the `updates` branch (so an APK can carry website changes before they are live; the pallet log switch, today's Manifest date and descriptions on any pallet went live on the website with `main` `38c031c`) and its first signed copy is **Build 66 (Android 9)**. The second approved update, **Build 66 (Android 26)** (37 MB, run 44500412882, signed with the same key so it installs over the first and keeps its data), brought most of what is described below. The third, **Build 66 (Android 43)** (37 MB, GitHub run 44525475542, same signing certificate, 63 offline checks passed), adds the camera scanner's type, FSDU, Remove last and recent pallets, Carry on scanning, Bigger buttons for gloves, the upright aiming frame, full-strength buzzes, bars that follow the theme, bottom-sheet questions, the light tap, the Continue shortcut without the keyboard and the Scan by photo camera fix, and carries the two-page blank tally sheet. **Android 48** (GitHub run 44538164396) and **Android 57** (GitHub run 44557179403, built from commit `d4f92a2`) followed; Android 57 contains the changes listed below as "since Android 57" ("all in" in the camera scanner, the type colours, labels that fit, the app's look in the scanner, and full-width solid question sheets). After Android 57 the app got its own build number (`tools/android/build.json`), separate from the website's and started again at 1: **Android APK build 1** (built from GitHub run 59) is the first to show it. **Android APK build 2**, built from run 65 (GitHub run 44743751786), is the APK that adds descriptions on any pallet (`palletDesc`); its What's new says so. **Android APK build 3**, built from run 103 (GitHub run 45040214307; 78 MB, up from 37 MB, mainly because ML Kit's text reader is inside it; same signing certificate, so it installs over build 2 and keeps its data), carries the changes marked "since Android APK build 3" below (made on the `updates` branch, commits `1c7fb46` to `6929d5e`, 21 and 22 Nov 2026; not on the website). **Android APK build 4**, built and signed on 25 Nov 2026 from GitHub run 45618664200 (file `LPN-Pallet-Log-Android-APK-build-4.apk`, 41 MB), carries the changes marked "since Android APK build 4" below and the redesigned screens (commits `20083f2` to `b650471`, on `main` since `b650471`; Take manifest photo and Share log's delivery details are on the website too). How it is built, signed and installed: [installation](installation.md#android-app-offline-apk).

**Photo reading never worked in APKs up to Android APK build 2.** Android's app build treats files ending in `.gz` specially, so the photo reader's language data `eng.traineddata.gz` couldn't be found inside the APK: reading manifest photos (and **Read the printed LPN**) waited 90 seconds and gave up. Since Android APK build 3 the language data goes into the app unzipped, and each hand-started build reads the owner's manifest photos on a virtual phone and makes no APK unless every LPN is right (see [installation](installation.md#android-app-offline-apk)). On an older APK, install build 3 or read manifest photos on the website.

**What is the same.** Logging, the Manifest check (photos, PDFs, spreadsheets), exports, Saved deliveries, backups, Share log, the Guide and Settings all work as on the website, with the Android app's own site settings (`tools/android/config.js`).

**What is different:**

- **No Report a problem and no Share this app.** They need the internet or the website, so they are always switched off in the app; the Guide's privacy section says there is no Report button. **Download problem report** in Settings is still there.
- **Nothing about installing.** The Guide's "Install it on your phone" section, the **Install** part of Settings (**Show the install pop-up**) and the first-visit install pop-up are all left out, since the app is already installed; the Guide's other numbered sections still count up without a gap.
- **The privacy line about tools** reads "The Excel, PDF, barcode and photo reading tools are inside this app, so nothing is downloaded and the app never needs the internet." instead of the website's line about public code servers.
- **No Google backup.** The app's data (log, saved deliveries, settings) is not copied into Google's phone backups (`allowBackup=false`), so it stays on that phone only. Use **Settings → Download backup** to keep a copy; reinstalling after removing the app starts empty.
- **Its own settings file.** A feature switched off on the website stays on in the app, and the other way round. A change to the app's settings reaches phones only when a new APK is installed.
- **No default logo.** The app doesn't carry `logo.png`. **Settings → Add logo** still adds your own, and **Remove logo** takes it off.
- **Exports say they came from the app, with the app's own build number:** the "Made with" line, the Excel and PDF page footers and the PDF's hidden data (`app`) read "LPN Pallet Log (Android APK build <n>)", for example "LPN Pallet Log (Android APK build 1)", instead of the website's version and build. (APKs before Android APK build 1 wrote, for example, "LPN Pallet Log v4.0 (build 66, Android app)".)
- **Saving a file** (Excel, PDF, backup…) keeps a copy in **Documents › LPN Pallet Log** on the phone and shows a **Saved** bar at the bottom: "Saved <file name> in Documents › LPN Pallet Log." with **Open** (opens the file in another app, for example Excel or a PDF viewer), **Share** (Android's share menu, to email it, put it in Drive or send it to a printer app), **Save to…** (Android's own save screen, to put a copy in any folder or in Drive; afterwards "Saved a copy of <file name> where you chose.") and **✕** (close). The bar goes after 12 seconds unless one of its buttons has focus; Back closes it. Since Android 43 the bar, and the app's short messages (toasts such as "Scanner connected…"), sit just above the docked entry bar (Add and Scan) on a phone instead of covering it; with the entry bar hidden or slid away for the Manifest check they sit at the bottom as before. If the copy can't be kept (older Android), the share menu opens straight away instead, as before.
- **Sharing** (Email PDF, Share missing list and other share buttons) uses Android's share menu. Closing it counts as cancelled, not as an error. Since Android APK build 7, Email PDF first asks who it's for (see Email PDF asks who it's for, below).
- **Print** opens Android's own print screen with the PDF (A4 to start with). If that isn't possible, the PDF is saved and shared as above.
- **Barcodes** (Live scan, Scan by photo, Upload photo and Share log codes) are read by Google's ML Kit on the phone, which is part of the app, so it needs no internet. When a label has several barcodes (for example an LPN and a shipping code), a Share log code is used first, then an LPN, then anything LPN-shaped, so the LPN is the one logged rather than whichever barcode was read first.
- **Keep the screen on** (Settings) is done by the app itself, so it works without the browser's screen lock.
- **The screen:** on newer phones the app fits between the status bar and the navigation bar (and stays above the keyboard). Since Android 43 both bars take the app's background colour, following **Colours** in Settings, Follow phone and **Use the phone’s colours**, with dark icons when that colour is light and light icons when it is dark (before, they were always navy with light icons). It starts with a plain navy screen and its icon, and on Android 13 and newer the icon can follow the phone's themed icon colours.
- **Settings and the footer** show which Android build this is, for example "Android APK build 1": the Android app's own build number, the same one the exports show. (Earlier APKs showed the website build and the GitHub run number, for example "Android app: Build 66 (Android 57)"; an APK whose name isn't in the new form still shows "Android app: " and its name.) In Settings it is the first line of the **Android app** section (below), followed by "Data on this phone: <size>" (KB or MB).
- **Upright on phones.** On phones (smallest screen width under 600dp) the app stays in portrait while you move about; tablets still turn.
- **Text size follows the phone's.** When the phone's own text size changes, the app's **Text size** follows it: Extra large (1.25) when the phone's text is at 130% or more, Large (1.12) from 112%, otherwise Normal. On first opening at normal size nothing changes. A size chosen in Settings stays until the phone's setting changes again. Android doesn't enlarge the page a second time (the WebView's text zoom is fixed at 100%).
- **Android-style controls.** The tick boxes in panels such as Settings look like Android switches (still checkboxes for TalkBack and the keyboard), and buttons show a ripple where they are pressed (not with reduced motion). Buttons keep their text and position.
- **Smoother scrolling** on long logs (the WebView draws ahead of the scroll and Android keeps its renderer at high priority while the app is open).
- **Your data has room to grow.** The app keeps everything the website would keep in the browser's storage (capped at about 10 MB on Android) in its own storage instead, one file per item in the app's private folder, so a log can grow as large as the phone has room for. The first time an updated app opens, everything already saved is copied across once; the old copy is left as it was. Colours (Follow phone, two colours drive the whole theme, with a contrast warning; since build 41 the edges of boxes and buttons and any accent-coloured text, such as panel headings and links, are adjusted automatically so they stay readable with any chosen colours; since build 56 a mid-grey background gets dark or light text, whichever has more contrast, and the text and grey text (hints, placeholders, notes) are made darker or lighter until they are readable on it, while the quick themes look the same as before; since build 62 the warning colour, used for example for refused pallets, the seal note and "In testing" notes, is moved towards the text colour until it is at least 4.5:1 against both the chosen background and the cards), quick themes, logo, default pallet type, keep last type, warnings, sound, vibration, keep the screen on (build 62, see [Scanning](#scanning)), Simple view (build 66, off by default, see [Help buttons, Simple view and other build 66 additions](#help-buttons-simple-view-and-other-build-66-additions)), keyboard shortcuts on a computer (build 66, ticked by default, see [Paste, mute, copy and keyboard shortcuts](#paste-mute-copy-and-keyboard-shortcuts-build-66)), confirm scans, text size, site or store name (build 62, see [Exports](#exports)), date format (dd/mm/yyyy, mm/dd/yyyy, yyyy-mm-dd), test a handheld scanner (build 59, see [Scanning](#scanning)), include log copy in comparisons, forget remembered names, share this app (QR code and **Send the link**, build 50, see [Share this app](#share-this-app-build-50)), install pop-up, backup and restore, report a problem or idea, problem report. In the Android app, Settings starts with a line naming the Android build (see [Android app](#android-app-offline-apk)).

**Follow phone (build 46):** the tick box at the top of **Colours**, "Follow phone: dark (navy and orange) when the phone is in dark mode, light (light and blue) when it isn’t". When ticked, the app uses navy `#0c1830` with orange `#ff8a2a` while the phone or computer is in dark mode, and light `#eef1f6` with blue `#2563eb` otherwise, and switches straight away when the phone changes mode, without a reload. The message says "Colours now follow the phone’s light or dark mode." and the colour boxes show the colours in use. Choosing a colour with the picker or typing a hex code turns it off and keeps the colours that were showing (with your change); choosing a quick theme or **Reset to default colours** turns it off too. It is saved on the device (and in backups) with the colours.

**Logo** (under the colours): **Add logo** / **Change logo** picks an image that is kept on this device and used in the header and on exports. A saved logo is only used if it is a PNG or JPEG image stored in the app. `logo.png` next to the app is the default; when a custom logo is set, **Reset to default logo** (or **Remove logo** if there is no default) appears. The logo controls are no longer in the Delivery card.
