# Architecture

## Overview

A client-only progressive web app. There is no backend for the app itself: the browser renders the page, holds the state, builds the export files and stores everything in `localStorage`. GitHub Pages only serves static files. The one exception is **Report a problem or idea**, which posts to a small Cloudflare Worker (`tools/feedback-worker`, see [Feedback Worker](#feedback-worker-toolsfeedback-worker)); it is online at `https://lpn-feedback.jamie9904.workers.dev` since build 43; it is the only server the app sends data to.

```
┌──────────────── index.html ────────────────┐
│ config.js → core.js → scan.js → export.js → compare.js → panels.js │   (classic scripts, shared globals)
└──────────────────────┬─────────────────────┘
          localStorage (lpn*)     sw.js (cache)
                       │                │
              CDN libraries loaded on demand (ExcelJS, jsPDF, pdf-lib, pdf.js, ZXing, Tesseract)
```

## Data model

- **Current log** (`lpnlog`): `{rows:[{lpn,type,fsdu,dmg?,desc?,ref?}], date, recv, notes, expect, trailer, sealIn, sealOut, exp}`. Written by `save()` after every change. `exp` is `{at, sig}`: when the log was last exported and a hash of its rows (`logSig()`) at that moment, so a later change can be detected. `dmg` (build 49) is the damage note ("Crushed", "Wet" or the person's own words); it is only present on damaged pallets. `logSig()` hashes `lpn|type|fsdu` plus `|dmg` when there is one, so marking, changing or removing damage after an export counts as not yet exported. `desc` (build 55) is a pallet's description (up to 60 characters), mostly used for pallets logged as "No LPN n"; `logSig()` adds `|d:<desc>` for it. `ref` (build 62) is `true` on a refused pallet (sent back with the driver) and left off otherwise; `logSig()` adds `|r` for it.
- **App-made PDFs** carry `LPNLOG2:` + URL-encoded JSON in the keywords: `{app, d, r, n, e, t, si, so, rows:[[lpn, type, fsdu 1/0]]}`; since build 49 a damaged pallet's row has a fourth item, the damage note (`[lpn, type, fsdu, dmg]`). Since build 55 a row with a description has a fifth item, `[lpn, type, fsdu, dmg or "", desc]`. Since build 62 a refused pallet's row has a sixth item, `1`: `[lpn, type, fsdu, dmg or "", desc or "", 1]` (the fourth and fifth are written as `""` when empty, so the sixth keeps its place). Rows of pallets that aren't refused are written as before, so a PDF from build 62 without refused pallets has the same shape as one from build 61. `app` is the version text from `appVersion()`; importing ignores it.
- **Saved deliveries** (`lpnhist`): array of the same shape plus `id` and `saved` timestamp. `pruneHist()` keeps an entry when the later of its `date` (if it is a `yyyy-mm-dd` date) and the local day of its `saved` timestamp is on or after `keepFrom()`, the start of last week (weeks start on Sunday). An entry with neither a usable date nor a usable `saved` is kept. Before build 60 it used `date` alone (falling back to `saved` only when `date` wasn't a date), so a delivery dated before last week was removed in the same `pushHist()` call that added it. **Import an exported log** (`#histFile` in `initHistory()`) runs `parseExported()`, stops with "No pallets were found in that file." if there are no rows, then calls `pushHist()` with `saved` set to now and the read details and rows, and shows "Imported n pallet(s). Tap Open to use it." in `#histMsg` (singular for one; with the Mixed-type sentence when `unk` is above 0). Since build 61 it no longer checks whether the entry survived pruning: with today's `saved` it always does, so the older-than-last-week message and **Load it into the log** button were removed. `pushHist(entry)` adds an `id`, puts the entry first, runs `pruneHist()`, caps the list at 50 and returns the `id`. `pruneHist()` also runs at load, in `initHistory()` and in `fillCmpHist()` (`compare.js`).
- **Manifest numbers** (`lpncmpman`): the raw text of the manifest box, so live tracking survives a reload.
- **Settings and preferences**: `lpncfg`, `lpntheme` (`{bg, ac}`, plus `follow: true` when Follow phone is on, since build 46), `lpnlogo`, `lpnnames`, `lpnpresets`, `lpncmppfx`, `lpncmpdate`, `lpnmergelog`, `lpnbackup`, `lpninstallshown`, since build 62 `lpnunexp` (the `logSig()` of the last log answered with **Not now** on the reminder card; one value, overwritten each time), and since build 54 `lpnzoom` (the last Live scan zoom, a number as text such as `"3"`, written by `setZoom()` after the camera accepts it; read by `zoomSetup()` and used only if it lies between the camera's lowest zoom and its highest (capped at 5); like the other preference keys it goes into backups).
- **Welcome and what's new (build 50)**: `lpnwelcome` (since build 51 `"ask"` from the very first visit until the welcome card is answered, then `"1"`; in build 50 it was only ever `"1"`) and `lpnseenbuild` (the build number from `appBuildP`, written on every load where it is known). See "Welcome and what's new card" under Main flows.
- **Report name (build 50)**: `lpnfbname`, the name last sent from the report box (tidied, at most 60 characters); removed when a report is sent with the name box empty.

These three, like the other preference keys, are `lpn*` keys other than `lpndiag` and `lpnfeedq`, so `backupNow()` puts them in backups and a restore copies them as they are (since build 51 the code comment on `lpnfbname` says so: "kept on this phone, and in its backups"; it isn't sent anywhere unless typed into a report). Because `lpnwelcome` is copied too, a backup made while it was `"ask"` brings the welcome card back on the phone it is restored to.
- **Unsent reports** (`lpnfeedq`): an array of report objects `{kind, text, app, report, id}` waiting to be sent by **Report a problem or idea** (no photos). `fbSave()` refuses to write a list of more than 5 items or more than 300,000 characters of JSON, and removes the key when the list is empty. Like `lpndiag` it belongs to the device: `backupNow()` and the restore's copy of current values leave it out, and `checkBackup()` ignores it.
- **Problem log** (`lpndiag`): an array of `{t, k, m}` (ISO time, kind cut to 20 characters, message cut to 300 characters), at most 300 entries, oldest dropped first. Written only by `diag()`. It belongs to the device: `backupNow()` leaves it out, `checkBackup()` ignores it, and a restore neither removes nor replaces it.

The site settings (`config.js`) are not stored on the device: they come with the app files, and `SITE` is worked out again on every load. The Clear trailer, seals and notes button stores nothing of its own; it writes the emptied fields through `save()` into `lpnlog`.

Dates are stored as ISO `yyyy-mm-dd` and only formatted for display (`ukDate()` follows the Date format setting).

### Saved data is tidied when it is read

Anything in `localStorage` may have come from a restored backup file, so it is checked before use by helpers in `core.js` (and one in `compare.js`). Anything that doesn't fit is dropped or replaced, rather than stopping the app.

| Helper | Used for | What it keeps |
|---|---|---|
| `isTxt(v)` | everywhere below | true only for a string or a number |
| `cleanRows(a)` | `rows` in `lpnlog` and in each saved delivery | entries that are objects with a text `lpn` that isn't blank; `lpn` trimmed and cut to 100 characters; `type` one of `TYPES`, otherwise `"Mixed"`; `fsdu` turned into true/false; `dmg` kept only if it is text (`isTxt()`), with runs of spaces made one, trimmed and cut to 60 characters, and left off when that is empty (build 49); `desc` the same way (build 55); `ref` kept only when it is exactly `true` (build 62) |
| `cleanDel(o)` | the delivery fields (`DEL_F`) of `lpnlog` and each saved delivery | each field as text cut to 2000 characters (anything else becomes `""`); `date` only if it is `yyyy-mm-dd`; `exp` only if `at` is an ISO time (`isoTime()`) and `sig` is a string, otherwise `null` |
| `cleanHist(a)` | `lpnhist` | each object entry through `cleanDel()` plus `id` (made up as `r<time><n>` if missing), `saved` (an ISO time or `""`) and `rows` through `cleanRows()` |
| `cleanNames(a)` | `lpnnames` | non-blank strings, trimmed, cut to 60 characters, at most 6 |
| `cleanCfg(c)` | `lpncfg` | only keys the default `cfg` has, with the same type; `size` must be `1`, `1.12` or `1.25`, `dateFmt` `uk`, `us` or `iso`, `defType` one of `TYPES`; since build 62 `awake` (boolean, default `true`) and `site` (string, default `""`), with `site` tidied (runs of white space made one, trimmed, cut to 40 characters) |
| `okLogo(v)` | `lpnlogo` (in `loadLogo()` and restore) | only a `data:image/png` or `data:image/jpeg` base64 data URL, so a saved logo can't point at another website |
| `normList()` (in `compare.js`) | `lpnpresets` | presets whose list is still a usable prefix list after normalising |

`load()`, the `hist` and `names` set-up in `panels.js`, the `cfg` set-up in `core.js`, `loadLogo()` and the `lpnpresets` set-up in `compare.js` all go through these. The delivery notes box also has `maxlength="2000"` in `index.html`, matching the limit in `cleanDel()`.

## Main flows

**Adding a pallet**
`Enter`/Add → `tryAdd()` runs `lpnIssues()` (duplicate, format, prefix list, digit count via `lpnDigitsOk()`) → either the warning bar (Skip / Add anyway) or `addValue()` → `rows.push()` → `save()` → `render()` → `summary()` (totals, expected count, live manifest progress, entry-bar counter) → confirmation toast.

While a warning waits, `pendingAdd` holds the LPN and `tryAdd()` returns `false` straight away. `add()` (Enter or Add) checks `pendingAdd` first: if set, it leaves the typed LPN in `#lpn`, selects it, shows "Answer the check first (Skip or Add anyway), then add <LPN>." in `#msg` and plays `sfx("warn")`, without calling `tryAdd()` (build 41; before, the box was cleared and the LPN lost). Live scan's `onCode()` ignores codes while `pendingAdd` is set. A `keydown` listener in `core.js` clicks `#chkSkip` on Escape when `#chkBar` is showing, unless `#panel` or `#instBox` is open or the key came from an `INPUT`, `SELECT` or `TEXTAREA` other than `#lpn`. It is registered before the Escape listeners in `panels.js` that close the panel and install box. `hideCheck()` clears `pendingAdd` and hides the bar.

Since build 63 `tryAdd(v, scan, ask)` has a third argument: `ask`, a sentence that forces the check bar even when `lpnIssues()` finds nothing and `cfg.confirmScan` is off (used for an LPN read from a label's printed text). The bar text is `ask + " "` followed by the usual "Check <v>: <issues>." when there are issues, otherwise "Add it as <type>?" (instead of "Scanned <v> as <type>. Add it?"). The button is **Add anyway** with issues and **Add** without, as before.

**Entry-bar count (`fitDock()`, `core.js`, build 56).** `summary()` builds a list of wordings, longest first: with a manifest `["f/t on manifest", "f/t", "f"]`; with Expected pallets `["n of x logged", "n/x logged", "n/x", "n"]`; otherwise `["n logged", "n"]` (`[""]` with no rows and no manifest). `fitDock(dc, opts)` stores the list in `dc.dataset.opts` as JSON and sets `#dockCnt`'s text to each in turn until `scrollWidth <= clientWidth` (or the last one, or when `clientWidth` is 0, so the first one while the bar is hidden). A `resize` listener and `applyCfg()` (text size) run `fitDock()` again from the stored list. `title` and `aria-label` keep the full wording. Before build 56 the short form was used whenever `innerWidth < 400`.

**FPP pallets (`addValue()`, `openDesc()`, `core.js`, build 56).** At the end of `addValue(v, o)`, when `o.type === "FPP"`, the value isn't a no-LPN name, `feat("fppDesc")` is on and Live scan isn't running (`scanning` false), it calls `openDesc(rows.length - 1)`. Every add with a type goes through `addValue()` (typed or scanner Enter, Add anyway, Scan by photo), so all of them open the box; Live scan doesn't, so the keyboard doesn't cover the camera. `openDesc(i)` (also used by `addNoLpn()` now) sets `focusDesc = true` on the next tick and clicks `#body .lpnedit[data-i="i"]`.

**LPN digit counts (`lpnDigitsOk(x)`, `core.js`, build 39).** The one digit-count rule. It upper-cases `x`, removes spaces and needs letters followed by digits (anything else returns `false`). Prefix `IM` (full pallet picks, 2 letters) passes with 10 or 11 digits; any other prefix with 9 or 10. It is used by `lpnIssues()` (warning "has N digits (IM numbers have 10 or 11)" for `IM`, otherwise "has N digits (usually 9 or 10)"), `oddNote(id)`, `photoLpns()` (`.odd`) and the left-out rule in `tidyReads()`. Before build 39 each place had its own 9-or-10 rule, so an 11-digit `IM` number was warned about and a 9-digit one was not.

**`maybeLpn(x)` (`compare.js`, build 40).** `lpnDigitsOk(x)`, or `IM` followed by exactly 9 digits (one digit short, probably a misread). It filters the left-out scans in `extractLpns()` and `lpnsFromText()` (1–3 letters + 9 to 11 digits) and the readings `photoLpns()` puts in `.skipped`, so a 9-digit `IM` number outside the prefix list is still named as left out (build 39 had dropped it).

**`oddNote(id)` (`compare.js`).** The "unusual number of digits" note after manifest or log numbers are read or typed. It splits the box `id` into trimmed, non-empty lines. A line that is letters followed by digits (spaces removed) is listed if it fails `lpnDigitsOk()`; any other line (for example `VLT-004040265` or `004040265`) is listed unless the digits at its end number 9 or 10 (the rule from before build 39, put back in build 40). Up to eight are named, then "and n more".

**Expected-count line**
`summary()` fills `#expInfo` from Expected pallets (`#expect`). If a manifest is loaded and `manState().total` equals the expected number, the line is hidden (the manifest progress line already says the same). Otherwise its class is `expinfo prog` while under the expected count (normal text colour, "(n to go)"), `expinfo ok` when equal (green, "✓ all accounted for") and `expinfo bad` when over (red, "(n more than expected)").

**Undo last pallet**
`#undoLast` pops the newest row and offers Undo through `showUndo()`. Its visibility is set in `summary()`; CSS shows it on phones only.

**Undo bar (`showUndo(text, fn)`, build 42)**
Until build 61 `showUndo()` showed `#undoBar` with the text, hid `#flash` (the "Added" note), and set `#undoBtn` to hide the bar and run `fn`, so each new change replaced the one before. Since build 62 it pushes onto a list (see Undo list below) and `undoBar()` does the showing. The bar hides after 20 seconds (9 before build 42); if focus is inside the bar at that moment, it checks again every 3 seconds instead. On phones (`max-width:759px`) CSS makes it `position:fixed`, centred, `bottom: calc(var(--dockh,220px) + 10px)` (just above the entry bar, `z-index:31`, at most 520px wide); with `body.cmpfocus` (entry bar stepped aside) it sits at `bottom:20px`. `flashAdded()` places `#flash` above the entry bar on phones, plus the Undo bar's height and 8px when the Undo bar is showing.

**Undo list (`undoStack`, `showUndo(text, fn, whole)`, `undoNow()`, `core.js`, build 62)**
`undoStack` is an in-memory array (not saved, so a reload empties it). `showUndo(text, fn, whole)` pushes `{text, fn, whole: !!whole, sig}`, where `sig` is `undoSig()` (`logSig()` plus `|` and every `DEL_F` field value) for a whole-log change and `""` otherwise, drops the oldest past 10 (`shift()`), and calls `undoBar()`. The three whole-log callers pass `whole` true: Clear all (`scan.js`, text "Cleared n pallet(s)", singular for one since build 62), Clear trailer, seals and notes (`core.js`) and `newDelivery()` (`panels.js`). Removing a row (✕), `#undoLast` (↶) and the edit `finish()` call it without.

- `undoBar()` clears the timer, runs `syncUndo()`, and hides `#undoBar` when the list is empty; otherwise it writes the newest entry's text to `#undoTxt` and " (n earlier)" to `#undoN` (`span.undon`, normal weight; empty when there are none), shows the bar, hides `#flash`, sets `#undoBtn.onclick` to `undoNow()` and starts the 20-second timer (re-checking every 3 seconds while focus is in the bar, as before).
- `syncUndo()` shows `#undoMore` (a plain `button`, text "Undo", placed before `#expBtn` in the `.act` row in `index.html`) while the list has entries, with `aria-label` "Undo: <text>" plus " (n earlier change(s) can be undone after it)". `#undoMore.onclick` is `undoNow()`.
- `undoNow()` returns at once while `window.__histExporting` is set (a saved delivery's rows stand in for the log during its export). It pops the newest entry. For a `whole` entry whose `sig` no longer equals `undoSig()`, it empties the whole list, hides the bar, runs `syncUndo()` and writes to `#msg` "“<text without its full stop>” can’t be undone now, because the log has changed since" plus ", and nor can the n earlier change(s)" when there were others, then "."; `fn` is not run. Otherwise it runs `fn`, writes "Undone: <text>." plus " n more can be undone." to `#msg`, and shows the next entry with `undoBar()` or, with none left, hides the bar. If focus was on the bar or `#undoMore` and has been left on nothing (the body, or a hidden element), it moves to `#expBtn` (`preventScroll`).
- `undoClear()` empties the list, clears the timer, hides the bar and runs `syncUndo()`. `openHist()` (opening a saved delivery) and a successful backup restore in `initSettings()` call it.
- A `keydown` listener on `document`: `z` with Ctrl or Meta and without Shift or Alt, not from an `INPUT`, `SELECT` or `TEXTAREA`, not while `main` is `inert` (a panel, the install box or the report box open), and with something in the list: `preventDefault()` and `undoNow()`.

Entries that aren't whole are run whenever they are reached: a row removed with ✕ goes back at `Math.min(i, rows.length)`, one removed with ↶ goes back at the end, and an edit's undo steps set the old values back on the same row object.

**Editing an LPN in the log (build 42)**
`render()` puts a `button.lpnedit` in each LPN cell (`td.l`), with `aria-label` "Edit LPN <lpn>", `title` "Tap to edit" and `data-i` set to the row index. CSS makes it look like plain text (no background or border, at least 40px tall, full width, wraps). A click on the cell swaps it for an input; `finish(ok, key)` saves (or cancels) and re-renders, and when it was ended by Enter or Escape (`key` true) it focuses `#body .lpnedit[data-i="<i>"]`, found by row index rather than text, so it works after the LPN changes. Ending by blur doesn't move focus (since build 49, unless focus would otherwise be left on nothing; see Damaged pallet notes).

**Damaged pallet notes (`dmgRow(r, pick)`, `core.js`, build 49)**
When an LPN cell is opened for editing, `render()`'s click handler also builds a row with `dmgRow()` and puts it straight after the pallet's row (`tr.after()`), then scrolls it into view with `scrollIntoView({block:"nearest"})` so on phones it opens clear of the entry bar. The row is `tr.dmgrow` with one cell spanning the 5 columns, holding `div.dmgbox` (`role="group"`, `aria-label` "Damage for <lpn>"): a "Damage:" label, **None**, one button for each of `DMG_REASONS` (`["Crushed","Wet"]`) and **Other…**. Each button has `aria-pressed` true when it matches the current note (**Other…** when the note is not one of `DMG_REASONS`). The buttons cancel `pointerdown` and `mousedown`, so tapping them doesn't take focus from the LPN box first (a phone would otherwise end the edit before the tap lands). **Other…** shows `span.dmgother`: an input (`maxlength` 60, `aria-label` "Other damage, for example torn label", placeholder "What’s wrong?") filled with the current note if it is a custom one, and **Save**. Save or Enter tidies the text (spaces made one, trimmed, cut to 60) and picks it; empty text just focuses the box again.

Picking a choice calls `finish(true, key)` with `key` true when it came from the keyboard (`e.detail === 0`). `finish()` removes the row and, if the pick differs from the current note, sets or deletes `r.dmg` and (since build 55, together with any description and LPN change in one Undo bar; see Pallets with no LPN) shows Undo with "Marked <lpn> as damaged (<reason>)" or "Damage note removed from <lpn>" (Undo puts the old note back). The LPN text in the box is saved as before. The edit also finishes when focus leaves both the LPN box and the damage row (checked on the next tick after `blur`/`focusout`); Escape in either cancels. Tab (without Shift) in the LPN box moves to the first damage button, and Shift+Tab on that button moves back. After `render()`, focus goes back to `#body .lpnedit[data-i="<i>"]` when the edit ended from the keyboard, and also (with `preventScroll`) when focus was left on nothing because the table was redrawn.

In the table, a pallet with `dmg` gets class `dmg` on its row (a 3px inset red bar on the LPN cell, `--dg`) and a `span.dmgtag` under the LPN button reading "Damaged: <note>" in bold red, which wraps (`overflow-wrap:anywhere`) so a long note doesn't widen the table. The LPN button's `title` is "Tap to edit or mark damage" and its `aria-label` "Edit LPN <lpn>, damaged: <note>, or mark damage" (without the damaged part when there is no note). Pressed choices use `--dg` (a pressed None uses `--sel`); every damage button is at least 44px tall.

`extras()` adds a `["Damaged pallet", "<lpn>: <note>"]` pair for each damaged pallet, after Notes (and, since build 62, after the "Refused pallet" pairs). The exports that list Delivery Details from `extras()` therefore show them: the Excel log, `fallbackXls()` and `buildLogPdf()` (and so Print and Email PDF). The Manifest check's log copy (`logGridFrom()`) does not include damage notes, just as it leaves out notes and the trailer.

**Refused pallets (`r.ref`, `typeCounts()`, `core.js`, build 62)**
`render()`'s click handler builds the editor row when damage is on, `refused` is on, or `wantDesc`, and passes `refuse: feat("refused") ? (v, key) => { refPick = v; finish(true, key) } : null` to `dmgRow()`. In `dmgRow()`, `addRef()` (run after the damage box, or straight away when `opt.damage === false`) adds `div.refline` with `button.refbtn` (`type="button"`): text "Refused (sent back)" or, on a refused pallet, "Not refused" with class `on`; `aria-label` "Mark <lpn> as refused, sent back with the driver" or "Mark <lpn> as not refused". Like the damage buttons it cancels `pointerdown` and `mousedown`; its click calls `opt.refuse(!r.ref, e.detail === 0)`. `testNote("refused", rl)` adds the testing note in the line. Coming after the damage box, it is the last stop for Tab.

`finish()` handles `refPick` before the damage pick: when it differs from `!!r.ref` it sets `r.ref = true` or deletes it, adds "Marked <lpn> as refused (sent back)" or "<lpn> is no longer marked as refused" to `said`, and an undo step to `backs`, so it shares the edit's one Undo entry.

In the table a refused row gets class `refused` (CSS: a 3px inset bar in `--wn` on `td.l`) and `span.reftag` "Refused: sent back" under the LPN button, before any `dmgtag` (block, `--wn`, bold .85rem, `word-break:normal`, `overflow-wrap:anywhere`). **Camera request, Live scan reading and Zoom (`camAsk()`, `camApply()`, `zoomSetup()`, `setZoom()`, `scan.js`, build 54)**
`camAsk(w,h)` returns the `getUserMedia()` constraints `{video:{facingMode:{ideal:"environment"}, width:{ideal:w}, height:{ideal:h}, advanced:[{focusMode:"continuous"}]}, audio:false}`; every part is a preference, so a camera that can't meet it gives the nearest it has. `startScan()` stores the request in the global `CAM`: `camAsk(1920,1080)` on the `BarcodeDetector` path (passed to `getUserMedia()`), `camAsk(1280,720)` on the ZXing path (passed to `zxReader.decodeFromConstraints()`; the code comment says the slower ZXing reader, used on iPhones and Firefox, reads every pixel itself). Before build 54 both paths asked only for `facingMode`.

On the `BarcodeDetector` path the 250 ms `setInterval` now skips a tick while a `detect()` call is still running (a local `busy` flag, cleared in `finally`), so reads of a large picture never pile up on a slow phone. After `torchSetup()` and `zoomSetup()`, `startScan()` logs `diag("scan", "Live scan camera <width>×<height>")` from the track's `getSettings()`, with ", zoom <n>" when the settings report a zoom (inside `try`, so a browser without `getSettings()` logs nothing).

`index.html` wraps `#video` in `div.vidwrap` (`position:relative`) with `div#zoomRow.zoomrow` (`role="group"`, `aria-label="Zoom"`, `hidden`) after it, holding `button#zoomOut` (`aria-label="Zoom out"`, text `−`), `span#zoomVal` (`role="status"`, `aria-live="polite"`, starts `1×`) and `button#zoomIn` (`aria-label="Zoom in"`, `+`). `.zoomrow` is absolutely placed at `top:6px; right:6px` over the picture, `rgba(0,0,0,.7)` background, white bold text; its buttons are at least 44×44px with a 2px white border, transparent background, opacity .4 when disabled and a 3px white `:focus-visible` outline; `.vidwrap #video` is `display:block`. `.zoomrow[hidden]` is `display:none`. The row adds no height to the camera box.

- `zoomSetup(s)` (called by `startScan()` with `v.srcObject`, and by `stopScan()` with `null`) first sets `zoomTrack=null` and hides `#zoomRow`. Then, inside `try`, it reads the first video track's `getCapabilities()`; only if it has `zoom` with `max > min` does it keep the track, set `zoomMin` to the camera's minimum, `zoomMax` to the smaller of its maximum and 5, `zoomNow` to `zoomMin`, show the row and `showZoom(zoomMin)`. If `lpnzoom` parses to a number within `zoomMin`…`zoomMax` and differs from `zoomMin`, it calls `setZoom()` with it.
- `showZoom(v)` sets `zoomNow`, writes `v` rounded to one decimal plus `×` into `#zoomVal`, and disables `#zoomOut` at or below `zoomMin` and `#zoomIn` at or above `zoomMax`.
- `setZoom(v)` clamps `v` to `zoomMin`…`zoomMax`, calls `camApply(zoomTrack, {zoom:v})`, and on success `showZoom(v)` and writes `lpnzoom`; on failure it logs `diag("scan", "Zoom couldn't be set: <message>")` and leaves the display as it was (no message on screen).
- `#zoomIn` goes to the first of `ZOOM_STEPS` (`[1,1.5,2,3,4,5]`) above `zoomNow + 0.01`, or `zoomMax` if there is none; `#zoomOut` to the last step below `zoomNow - 0.01`, or `zoomMin`. `setZoom()`'s clamp keeps a step past the camera's range at its limit.
- `camApply(t, first)` is used by both Torch and Zoom. It calls `t.applyConstraints({width: CAM.video.width, height: CAM.video.height, advanced: […]})`, where the `advanced` list is `first` (the setting being changed), then `{zoom: zoomNow}` if the change isn't a zoom and a zoom other than `zoomMin` is set, then `{torch: true}` if the change isn't the torch and the torch is on, then `{focusMode: "continuous"}`. Each setting is its own `advanced` set, so a camera that refuses one still takes the others, and repeating the resolution, focus and the other setting means a change doesn't drop them (the code comment: "Changes a camera setting (torch or zoom) without dropping the others"). Before build 54 the Torch button called `applyConstraints({advanced:[{torch}]})` directly.

Zoom has no `FEATURES` key: it only exists inside Live scan, so it follows `liveScan`, and `torch` off doesn't touch it.

**Keep the screen on (`keepAwake(on)`, `syncAwake()`, `scan.js`, build 62)**
Before build 62 the screen wake lock was only asked for during Live scan. Now `syncAwake()` calls `keepAwake(document.visibilityState === "visible" && (scanning || cfg.awake))`. It runs once when `scan.js` loads, on every `visibilitychange`, from `stopScan()` (which used to call `keepAwake(false)`), and from the Settings tick box `#setAwake` (after `saveCfg()`). A passive `pointerdown` listener on `document` calls it when there is no lock and `cfg.awake` is on, so a request refused at start (some browsers need a tap first) is made again on the first tap. `startScan()` still calls `keepAwake(true)`.

`keepAwake(on)` makes one request at a time: the pending `navigator.wakeLock.request("screen")` promise is kept in `wakeAsk`, and a call that finds one waits for it and then runs `syncAwake()` again instead of acting, so the state wanted at the end wins and no second lock is left that nothing releases. On `on` it requests only when `navigator.wakeLock` exists and there is no lock (`wake`), and a lock's `release` event clears `wake` only if it is still that lock. Off releases the lock. Errors are swallowed (a refused request leaves `wake` empty). `cfg.awake` defaults to `true` and is in `lpncfg`; the Settings note (`HELP.settings`, after the Vibrate tick box) tells people to lock the phone themselves. There is no site switch.

**Backup and restore (Settings → Backup)**
`backupNow(msgId)` writes every `lpn*` key except `lpndiag` and `lpnfeedq` into `lpn-backup-<date>.json` (`{app:"lpn-pallet-log", version:1, saved, data}`) through `saveOnly()` and now returns `true` or `false`, so callers know whether the file was saved.

Restoring is done in steps, and nothing is changed until the last one:

1. **Choose the file** (`#bkUp` → `#bkFile`). If the file isn't JSON, or `app` isn't `"lpn-pallet-log"`, or `data` isn't an object, the message is "That isn’t a backup from this app."
2. **Check it.** `checkBackup(data)` builds a tidied copy and changes nothing. It skips keys that don't match `^lpn[a-z0-9]*$`, values that aren't strings, and `lpndiag` and `lpnfeedq` (the problem log and unsent reports never come from a backup). `lpnlog` goes through `cleanRows()` and `cleanDel()`, `lpnhist` through `cleanHist()`, `lpnnames` through `cleanNames()`, `lpncfg` through `cleanCfg()`, `lpnpresets` through `normList()` (names cut to 60 characters), `lpnlogo` is kept only if `okLogo()` passes, and `lpntheme` only if both colours pass `hexOk()` (it keeps `bg`, `ac` and, since build 46, `follow: true` when the file has exactly `true`). Other `lpn*` strings are copied as they are. If `lpnlog` or any of the JSON keys can't be read, it throws "That backup file is damaged, so nothing was changed."
3. **Ask.** `#bkMsg` says what the backup holds ("This backup has a log of n pallets and n saved deliveries…") and the row `#bkAsk` appears with **Replace my data with this backup** (`#bkGo`) and **Cancel** (`#bkNo`, "Nothing was changed.").
4. **Safety copy.** `#bkGo` first calls `backupNow("bkMsg")`. If that returns `false`, it stops and adds "Your data wasn’t replaced, because the copy of it couldn’t be saved first."
5. **Replace.** It logs "Restoring a backup" with `diag("backup", …)`, keeps a copy of every current `lpn*` value except `lpndiag` and `lpnfeedq`, removes them and writes the checked data. If writing fails (for example the browser is out of storage space), it removes what it wrote, puts the old values back and says "Couldn’t restore that backup because this browser ran out of storage space, so nothing was changed."
6. **Reload by hand.** On success it says "Backup restored. Make sure the copy of your previous data has saved, then reload the app to see the restored data." and shows `#bkDone` with **Reload the app** (`#bkReload`, `location.reload()`). There is no automatic reload, because on phones (iPhone asks first) the safety copy may still be waiting to be saved. Since build 62 it calls `undoClear()` first, because an undo before the reload would write the old log over the restored data.

**Opening PDFs**
Every PDF that pdf.js reads is opened by `openPdf(bytes)` in `compare.js`, which is `pdfjsLib.getDocument({data:bytes}).promise`. Its three callers each run `loadPdfJs()` first.

`loadPdfJs()` loads pdf.js 6.4.299, the "legacy" build (made for older browsers and phones). That build is an ES module, so it is loaded with a dynamic `import()` rather than `loadScript()`. The addresses are in `PDFJS_SRC`: jsDelivr first, then unpkg (cdnjs only hosts the modern build), each with a 15-second limit. The first one that loads becomes `window.pdfjsLib`, and `GlobalWorkerOptions.workerSrc` is set to the matching `pdf.worker.min.mjs` on the same host (pdf.js wraps a worker from another site itself). If `window.pdfjsLib` is already there it returns straight away. If both hosts fail it throws `PDF_LOAD_MSG`: "The PDF reader couldn’t load. Check you’re online, then reload the page and try again. Very old phones can’t read PDFs: type the numbers in the box instead." The service worker saves both files in `lpn-libs-v2` the first time they load, so PDFs can be read offline after one online read.

The three callers:

- `readPdf()` (`compare.js`): a manifest PDF in the Manifest check. It reads the text layer, and if no LPNs are found it renders up to 20 pages to a canvas (scale 2) and reads them with OCR. Both steps use the document `openPdf()` returned.
- `readLogPdf()` (`compare.js`): a log PDF in the Manifest check. It tries the `LPNLOG2:` (or older `LPNLOG|`) keywords first, then the column under the `LPN` heading, then falls back to `readPdf()`.
- `parseExported()` (`panels.js`): importing an exported log PDF in Saved deliveries, which only accepts PDFs with `LPNLOG2:` keywords.

The `LPNLOG2:` data could have been edited by someone, so both readers take only plain values from it: a value is used only if it is a string or number (`isTxt()`), cut to 2000 characters, and anything else (for example an object that ExcelJS would write as a formula or link) becomes `""`. `rows` must be an array of arrays whose first item is non-blank text; the LPN is trimmed and cut to 100 characters. `parseExported()` also keeps the date only if it is `yyyy-mm-dd`, and takes a row's fourth item as the damage note (same plain-text rule, spaces made one, trimmed, cut to 60; left off when empty). In `readLogPdf()` the same applies to the date and receiver that go into the log copy tab (`logGridFrom()`).

Where the message appears: importing in Saved deliveries and loading a log PDF in the Manifest check show the error's own text, so they show `PDF_LOAD_MSG`. The Manifest check's PDF button (`#cmpPdfFile`, several files at once) stops at the first file that fails with `PDF_LOAD_MSG` and shows only that message, instead of listing every file as unreadable.

The protection against harmful PDFs is the pdf.js version: 6.4.299 is past the known flaws where a crafted PDF could run code (CVE-2024-4367, fixed in 4.2.67; CVE-2026-16633 / GHSA-hq66-cqwq-w95j, which affected 5.6.83 up to 6.2.108). pdf.js 6 no longer compiles anything from a file, and a PDF's own scripts only run in the pdf.js viewer, which the app doesn't use. See [decisions](decisions.md#pdfjs-6-the-legacy-build-loaded-as-a-module). pdf-lib (`PDFLib.PDFDocument.load()` in `export.js`, used to add the uploaded log PDF to the manifest check PDF) does not go through `openPdf()`: it only copies the file's objects into the new PDF and does not run anything from it. `buildCmpPdf()` deletes each copied page's `/AA` (page-open actions, which can be scripts) and `/Annots` (links and other annotations) before adding it, so a log PDF from outside can't pass them on in the file that gets emailed and printed.

**Manifest check**
Numbers come from `readPdf()` (text via pdf.js, scanned pages via OCR), `ocrLpns()` (Tesseract with image clean-up and close-up re-reads) or typing. `extractLpns(text, any)` (photo text) matches `prefix + 8–12 characters` with at least six digits, then repairs look-alike characters in the number part (O/D→0, I/L→1, S→5, B→8, Z→2); with `any` true it ignores the prefix list and takes any 1–3 letter prefix. `lpnsFromText()` (PDF text) matches `prefix + 8–12 digits` with no repair. `cmpData()` normalises both lists and classifies each LPN as matched, missing or log only.

**Pallets with no LPN in the comparison (build 55).** `cmpData()` takes the de-duplicated log lines, counts those that pass `isNoLpn()` (`noLpn`) and matches only the rest; it returns `noLpn` and `cnt.noLpn` as well, and only stops with "Add the LPN log first…" when there are neither LPNs nor no-LPN lines. When `noLpn` is above 0: `renderCmp()` adds "No LPN (check by hand): <n>" to `#cmpSum`; `cmpShareText()` adds a fifth line "Pallets with no LPN (check by hand): <n>"; the comparison sheet (`#cmpGo`) adds `["No LPN pallets", n]` to the right-hand summary box after "⚠ Log only", puts "     No LPN: n" at the end of its title line, and moves the second side box's rows down by one (`nl`) so the box borders still fit; its row height also allows for a wrapped right-hand label (`xlLines(label, 25)`); `buildCmpPdf()` adds a "No LPN pallets" row to the Summary table. `oddNote()` skips no-LPN lines. The uploaded log's label counts them apart ("<file>: n LPNs found and m with no LPN"), and **Use current log** and the saved-delivery picker label the log as "n pallet(s)" instead of "n LPNs".

**Reading a photo (`ocrLpns()`, builds 35 to 37).** Manifest photos, log photos (`readPhoto()`, `readLogPhoto()`) and scanned PDF pages all go through it:

1. `prep(f)` scales the photo (long side up to 2400px, at most 3×; larger photos down to 3200px), turns it grey (0.299 R + 0.587 G + 0.114 B), then makes it black and white against the local paper background. The page is divided into square cells about 1/20 of the longer side (at least 8px), each cell's average grey is worked out in JS, and the background at each pixel is blended bilinearly between the four nearest cell centres. A pixel darker than 0.85 × its background becomes black, everything else white. No second full-size canvas is made and no browser scaling is used for the background, so every browser gives the same result.
2. The main Tesseract pass uses page segmentation mode 11 (sparse text) with the letters-and-digits whitelist.
3. Since build 57 the words are first passed through `ocrWordCands(words)` (see below), which gives one candidate `{raw, first, bbox, lab}` per word that is one LPN. Each candidate (before build 57, each word that gave exactly one match from `extractLpns(word, true)`) is re-read close up (`cropScaled()`, mode 7, single line). Each becomes an item `{raw, first, again, lab}`: the word's raw text, the first reading, the close-up reading (or `null`) and (build 57) whether it was printed after an LPN label. Matches in the whole page text that no word gave are added as `{raw: x, first: x, again: null, whole: true}` (build 37: `whole` marks them as whole-page text readings, which don't get the double vote below). After tidying, `ocrLpns()` keeps the item list in `window.__ocrItems` so the photo reading check (`tools/ocr-check`) can show what the reader saw.
4. `photoLpns(items)` runs `tidyReads(items)`, logs any readings it left out (`.ignored`) as an `ocr` problem log entry "Ignored as not looking like this page's LPNs: <readings>", then keeps the readings that pass `okPfx()` (all of them when the prefix list is empty). Readings outside the list that pass `maybeLpn()` (since build 40; `lpnDigitsOk()` in build 39) are returned as `.skipped`. Since build 37, readings `tidyReads()` left out that pass `lpnDigitsOk()` are returned as `.odd`, so the per-photo note can name them. Since build 45 it also returns `.mended`: the numbers `tidyReads()` changed to match the page, without repeats, keeping only those still in the result (so a mended number dropped by the prefix list isn't named).

**One reader per batch (build 41).** `ocrLpns(f)` only queues the work: it chains `ocrLpnsNow(f)` onto the promise `ocrQ` (failures swallowed in the chain), so reads run one at a time even when manifest photos and a log photo are read at once. Without the queue, two reads would share the reader and one batch's `setParameters()` (mode 11 for the page, mode 7 for close-ups) could change the other's in the middle of a read. `ocrLpnsNow()` gets the reader from `ocrWorker()`, which reuses `ocrW` (the promise of a running reader) or starts one with `Tesseract.createWorker("eng")`, raced against a 90-second timer. If the timer wins, the reader that finishes starting later is terminated rather than left running. `ocrWorker()` also cancels the pending idle close. When the read ends, the `finally` block calls `ocrDone(w, ok)`: on success it sets a 15-second timer (`ocrIdle`) that terminates the reader and clears `ocrW`; on any failure it terminates the reader at once, so the next photo starts a fresh one. `ocrW` is only cleared if it still points to the reader being closed. Each `recognize()` (the page pass and each close-up) goes through `ocrRead(w, img)`, which fails after `OCR_READ_MS` (120 seconds) with "The photo reader stopped. Try the photo again." and `stuck: true`. A failed close-up normally just leaves `again` as `null`, but a stuck one is thrown on (`e.stuck`), so a hung reader fails the photo instead of each close-up waiting 2 minutes. Before build 41 each photo started and terminated its own reader.

**Sideways and upside-down photos and freeing canvases (builds 46 and 47).** `ocrLpnsNow()` now does the reading in `ocrCanvas(w, cv)`, which runs steps 2 and 3 above on one canvas and returns `{out: photoLpns(items), items, r}`. It reads the `prep()` canvas first. If the result has no LPNs, no `.skipped` and no `.odd` (nothing LPN-like at all), it calls `turnCanvas(cv, 90)`, a new canvas with width and height swapped and the image drawn rotated (smoothing off), and reads that; if that still finds nothing, it tries `turnCanvas(cv, 270)`, and since build 47 then `turnCanvas(cv, 180)` (the loop is `for (const deg of [90, 270, 180])`; sideways first because phones are more often held that way). For 180° `turnCanvas()` keeps the width and height as they are (it only swaps them when `deg % 180 !== 0`). The first turn that finds something is used and the result gets `.turned = 90`, `270` or `180`; each try is logged with `diag("ocr", "Nothing found, so the photo was turned <deg>° and read again: n LPNs found.")`, and the main `ocr` entry adds "(turned <deg>°)". At most four page reads are made (three before build 47). While a manifest photo batch runs, `ocrSay` is set to show "Photo n of n: No numbers found, so turning the photo to try again…" in `#cmpMsg`; it is `null` for log photos and scanned PDF pages, which are turned too but show nothing. `readNote()` adds "The photo was upside down, so it was turned to read it." when `.turned` is 180 and "The photo was sideways, so it was turned to read it." for any other `.turned` value. Canvases that are no longer needed are emptied (`width = height = 0`) as soon as they are replaced, and in the `finally` block both the canvas used and any turned copy are emptied, because phones (Safari above all) give canvas memory back late.

**Words to candidates (`ocrWordCands(words)`, `compare.js`, build 57).** Shared by `ocrCanvas()` and the `cli` engine of `tools/ocr-check/check.js` (which builds the same `{text, bbox}` words from the Tesseract command's TSV), so the check and phones handle words the same way. For each word, `lab` is true when the word before it is `LPN` or `LPN:` (any case; the reader may lose the colon). When the word is labelled, gives no match itself, is 1–3 letters plus 2–8 digits, and the next word is 1–8 digits only, the two are joined if the joined text passes `lpnDigitsOk()`, the two boxes overlap vertically by at least 0.6 of the smaller word height, and the gap between them is between minus one and plus one word height; the joined box covers both and the next word is skipped. A word that then gives exactly one match from `extractLpns(text, true)` becomes a candidate. A labelled word that is 9 or 10 digits only goes on `out.noLetters`. `ocrCanvas()` appends each of those to the result's `.odd` as `"LPN <digits>"` and logs `diag("ocr", "Read after LPN: without its letters: <digits>")`; because they are in `.odd`, a photo with only those is not turned (the turn loop's `none()` test). `extractLpns()` also skips any match whose prefix is `LPN`, so the label is never read as a prefix in the whole-page text.

**`tidyReads(items)`** works on one photo at a time:

- **Page pattern.** Each distinct number votes for each shape (prefix + digit count, e.g. `VLT#9`) of its first and close-up readings. When the raw text had O, D or Q straight after the prefix letters and the reading has at least 10 digits starting with 0, it also votes for the shape with that 0 dropped. Since build 37 a vote is weighted: a first reading that is exactly the raw text (no look-alike letters turned into digits) and not a whole-page text reading (`whole`) counts 2, everything else 1, and one number gives a shape at most its highest weight. A shape counts only if it appears in at least 2 numbers; for each prefix the shape with the highest total weight is that prefix's pattern. The weighting means a tie between, say, 9 and 10 digits goes to what was printed plainly (on GitHub's real reader, two of three `RUN` numbers read with an O between `RUN` and the 0s).
- **Choosing a reading.** With no pattern, the close-up reading is used (or the first if there is none), except (build 57) when the item isn't `whole`, its first reading equals the raw text with spaces removed (in capitals), and the close-up has the same prefix and only adds a `0` at the start of the digits (`RUN0001840861` for `RUN001840861`): then the first reading is used and pushed onto `.mended`, so the note asks for it to be checked. Otherwise the first reading that fits a pattern is used, checking the first reading before the close-up, because the close-up is of the black-and-white image.
- **Mending.** If neither fits, the close-up then the first reading are tried against each pattern: a reading of the right length whose prefix characters are the pattern's letters or a look-alike digit for them (`LOOK`: 0 for O/D/Q/U, 1 for I/L/T/J, 2 for Z, 5 for S, 6 for G, 8 for B) gets the pattern's prefix (`VL1004040355` → `VLT004040355`); a reading one longer that starts with the prefix and `0` loses that `0`. A mended number that equals another number's first reading on the page is not used. An extra 0 is only dropped when the raw text had O, D or Q straight after the prefix. Anything not mended is kept as read. Since build 45 each mended number that is used is pushed onto a list attached to the result as `.mended` (a number read twice appears twice; `photoLpns()` removes the repeats).
- **Leaving out made-up codes (builds 36 and 37).** The result is an array of readings with an `.ignored` array attached. When the page has at least one pattern, a reading whose prefix matches no pattern's prefix goes into `.ignored` instead of the result if it fails `lpnDigitsOk()` (build 39; before, if its digit count was below 9 or above 10) (specks on the paper read as `DFA51400180` on a page of `VLT` numbers), or (build 37) if its prefix length differs from every pattern's prefix length (`CO1080002090`, `RR1004040021` and `L1121100001` among `VLT` numbers, as GitHub's real reader saw `vlt.jpg`). A reading of another prefix of the same length as a page prefix that passes `lpnDigitsOk()` is kept (it may be a real LPN and is reported by the prefix list if it isn't listed), and so is a short or long reading of a page prefix (`QUB00189918` next to `QUB` numbers). Prefixes in `KNOWN_PFX` (`["IM"]`, the two-letter prefix used for full pallet picks) are never left out, whatever the rest of the page looks like. With no pattern (for example a single reading) nothing was left out before build 57.
- **`KNOWN_ONE` and show-through (build 57).** `KNOWN_ONE` (`["V", "R", "Q"]`, single-letter prefixes real LPNs use) exempts a reading from the prefix-length rule above when it passes `lpnDigitsOk()` and its item has `lab`. On a page with no pattern, the prefixes of labelled readings form a set; when that set isn't empty, an unlabelled reading whose prefix isn't in it goes into `.ignored`, unless its prefix is in `KNOWN_PFX` or it is a `KNOWN_ONE` prefix with an LPN's digit count (no label needed here). `photoLpns()` then names those with an LPN's digit count in `.odd` as before.

**Numbers left out by the prefix list.** When a prefix list is set, PDF text (`lpnsFromText()`) also scans for any 1–3 letters followed by 9 to 11 real digits, keeps those that pass `maybeLpn()` (build 40: `lpnDigitsOk()` or `IM` + 9 digits; `extractLpns()` does the same for photo text), and attaches the ones not kept to the result as `.skipped`; `skippedOf(all, kept, pf)` removes duplicates, numbers already kept, and numbers that start with a listed prefix followed by a digit. For photos, `photoLpns()` reports tidied readings outside the list that pass `maybeLpn()`, so a look-alike reading that was mended to a listed prefix is kept, not reported. With an empty prefix list `.skipped` is empty. `readPdf()` carries the text layer's `.skipped` and adds those from OCR'd pages.

## Phone layout notes

## Feedback Worker (`tools/feedback-worker`)

A Cloudflare Worker (`worker.mjs`, configured by `wrangler.toml`: name `lpn-feedback`, `REPO = "Jamie9904/lpn-feedback"`, `ALLOWED_ORIGIN = "https://jamie9904.github.io"`, and the GitHub token as the secret `GITHUB_TOKEN`). The site is public and can't hold a GitHub key, so the Worker holds it. It is not part of the site and not in the site zip.

- `OPTIONS` → 204 with CORS headers (`Access-Control-Allow-Origin` is always `ALLOWED_ORIGIN`). Anything but `POST /report` → 404. An `Origin` other than `ALLOWED_ORIGIN` → 403. No token or repo → 503 "Reporting isn't set up yet." A body over 2,400,000 characters → 413.
- `check(o)` validates: `website` must be empty (a field only spam robots fill in); `kind` must be `problem` or `idea`; `text` 1 to 4000 characters after trimming; `report` cut to 60,000; `name` (build 50) tidied the same way as in the app (whitespace runs made one, trimmed, cut to 60; `""` if not a string); `app` kept only if it matches `^LPN Pallet Log( v[\d.]+)?( \(build \d+\))?$`, so nothing else can reach the issue outside a text block; `photo` only as `data:image/jpeg;base64,…` whose data starts `/9j/` (JPEG bytes FF D8 FF), at most 1,600,000 bytes. Failures → 400 with a plain message.
- **Limits:** one Durable Object (`Limits`, `idFromName("all")`) counts across all of Cloudflare's servers: at most `PER_HOUR` = 10 reports an hour per address (`CF-Connecting-IP`), `DAY_ISSUES` = 50 reports and `DAY_PHOTOS` = 20 photos a day in total (UTC day). Over a report limit → 429; over the photo limit the report is still made without its photo, with a note. An alarm a day after the first count clears all its storage. Each address is stored with its report times (`ip:<address>`); times older than an hour are only dropped when that address reports again, so an address stays in the Durable Object's storage until the daily clear-out, up to about 24 hours after the first counted report of that period. It is only used for the hourly count. (Since build 51 the Guide's privacy section says the address "is kept for up to a day to stop spam", which matches this; build 50 said "for an hour", the window it counts towards the limit.)
- **Issue:** `issueOf()` gives the title "Problem: " or "Idea: " plus the first line (up to 70 characters, "…" if cut), and a body naming the kind and app version, with the text, then (build 50, only when there is a name) a "From:" line followed by the name in its own block, and the problem report (in `<details>`), each in a `~~~~text` block made by `block()` (any run of four or more `~` in the text is changed to `∼`), so they can't add links, mentions or formatting.
- **Order:** the issue is created first (`POST /repos/<REPO>/issues`). Then, if there is a photo, it is saved with `PUT /contents/photos/<yyyy-mm>/issue-<n>-<time>.jpg` and the issue body is updated (`PATCH`) with a link and the image. A failed photo step only adds a note; a failed issue never leaves a stray photo.
- **GitHub failures:** 401, 403, 429, 5xx or no answer → 503 ("It will be tried again", so the app keeps the report); any other status → 422, which the app doesn't retry.
- Answer: `{ok:true, issue, note}` or `{ok:false, error}`.

`.github/workflows/feedback-worker.yml` (**Deploy feedback Worker**) deploys it, by hand (`workflow_dispatch`) or on a push to `main` that changes `tools/feedback-worker/**` or the workflow (so the build 50 name change in `worker.mjs` redeployed it when it reached `main`). Its first step checks for the three repository secrets `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` and `FEEDBACK_GITHUB_TOKEN`: on a push with any missing it skips with a notice; run by hand it fails naming the missing ones. Then `npx wrangler@3.114.0 deploy` (the address goes in a notice; if the deploy fails, the lines after `ERROR` in wrangler's output, with colour codes removed and cut to 500 characters, become the error notice "Feedback Worker deploy failed", so Cloudflare's own reason shows without opening the log), a separate step that is the only one given `FEEDBACK_GITHUB_TOKEN` and passes it on stdin to `wrangler secret put GITHUB_TOKEN`, and a check that `OPTIONS <address>/report` with the app's origin answers 204. That check tries up to 24 times, 5 seconds apart (about 2 minutes), because a new workers.dev address can take a while to start answering; it then gives a notice with the `/report` address, or fails with "didn't answer after 2 minutes (HTTP …)" and a hint to run it again in a few minutes. Separately, the weekly health check (from the next release; on `updates` now) checks the Worker answers `OPTIONS /report` with 204, that `FEEDBACK_GITHUB_TOKEN` can read `lpn-feedback` and doesn't expire within 30 days, and warns if `tools/feedback-worker` changed on `main` after the last successful deploy (see [testing.md](testing.md#weekly-health-check)).

Run by hand, the workflow has a tick box input `test_report` ("Also send a test report", off by default). When ticked, a last step posts `{kind: "idea", text: "Test report from the deploy check. Safe to close.", app: "LPN Pallet Log"}` to `/report` with the app's origin. A 200 gives a notice that a test issue was made in `lpn-feedback`; any other answer fails with the HTTP code, the Worker's answer and a reminder that the GitHub token needs Issues read and write on `lpn-feedback`.

## Library loading and fingerprints (SRI)

`loadScript(src, test)` in `core.js` adds a `<script>` with `crossOrigin="anonymous"` and, if `src` is in the `SRI` map, `integrity` set to its `sha384-…` hash. The browser then refuses a file that doesn't match, so a changed copy on a CDN can't run in the app; the feature fails as if the library couldn't load. `SRI` lists both addresses (cdnjs and jsDelivr) of ExcelJS 4.4.0, jsPDF 2.5.1, jspdf-autotable 3.8.2 and pdf-lib 1.17.1, plus Tesseract.js 5.1.1 and ZXing 0.21.3 (jsDelivr only). `loadZX()` in `scan.js` builds its own script tag and sets the same two attributes from `SRI` (checking `typeof SRI==="object"` first).

pdf.js has no entry: it is loaded with `import()` (see Opening PDFs), not through a script tag. The files Tesseract fetches for itself (its worker, engine and language data, from jsDelivr and `tessdata.projectnaptha.com`) aren't checked either; the comment in `compare.js` says they load in a way that can't be checked.

**Photo reader failures.** `ocrLpnsNow()` and `ocrWorker()` turn any failure to load Tesseract, or to start its worker within 90 seconds (`Tesseract.createWorker("eng")` raced against a timer; the first use downloads the language data), into `OCR_MSG`: "The photo reader couldn’t load. Check you’re online and try again, or type the numbers in the box instead. (Reading photos needs iOS 16 or newer on an iPhone.)" Before throwing it runs `dropOcrCache()`, which deletes every saved file in the `lpn-libs*` caches whose address contains `tesseract` or `tessdata`, so the next try downloads them again.

## Security policy

`index.html` sets a Content Security Policy with a `<meta http-equiv="Content-Security-Policy">` tag in `<head>`, before the five app scripts. The exact text:

```
default-src 'self'; script-src 'self' https://cdnjs.cloudflare.com https://cdn.jsdelivr.net https://unpkg.com 'wasm-unsafe-eval'; worker-src 'self' blob:; child-src 'self' blob:; connect-src 'self' https://cdn.jsdelivr.net https://unpkg.com https://tessdata.projectnaptha.com https://lpn-feedback.jamie9904.workers.dev; img-src 'self' data: blob:; font-src 'self' data:; style-src 'self' 'unsafe-inline'; frame-src blob:; object-src blob:; base-uri 'none'; form-action 'none'
```

What each part is for in this app:

| Directive | Used by |
|---|---|
| `script-src` | The app's own scripts; `loadScript()` and `loadZX()` from cdnjs and jsDelivr; pdf.js `import()` from jsDelivr or unpkg; `'wasm-unsafe-eval'` for Tesseract's WebAssembly engine (no general eval) |
| `worker-src`, `child-src` | The pdf.js and Tesseract background workers (`child-src` for older Safari) |
| `connect-src` | `fetch` of app files and `sw.js` (`appBuildP`), library downloads made by the service worker, Tesseract's engine and its language data from `tessdata.projectnaptha.com`; `fbPost()` to the feedback Worker (`https://lpn-feedback.jamie9904.workers.dev`, that exact origin only, since build 43) |
| `img-src` | The logo (stored as a `data:` image), canvases turned into images |
| `font-src` | The self-hosted fonts in `fonts/` |
| `style-src 'unsafe-inline'` | `style` attributes and `style.cssText` set from code |
| `frame-src`, `object-src` | `printBuf()` loads the PDF into a hidden `<iframe>` from a `blob:` address |
| `base-uri`, `form-action` | Set to `'none'`: nothing can change the base address or submit a form |

`connect-src` names the feedback Worker's exact origin rather than all of `*.workers.dev`, so the page can't send data to any other Worker. `tests/groups/12-report.js` checks that the origin of `FEEDBACK_URL` is in `connect-src` (see testing).

Older Safari doesn't understand `'wasm-unsafe-eval'`, so reading photos needs iOS 16 or newer on an iPhone. A new library host, or a library that fetches from a new place, must be added to the policy, or it is blocked. See [decisions](decisions.md#content-security-policy-in-the-page-build-31).

## Offline and updates

`sw.js` pre-caches the app shell (with `cache:"reload"` to bypass the HTTP cache) and serves app files network-first with `cache:"no-cache"`, so a published change appears on the next load and the cached copy is only used offline. `sw.js` is in its own `SHELL` list, so the page can still read the build number from it when offline. Since build 50 `media/share-qr.svg` (the Settings QR code) is in `SHELL` too, so it shows offline, and since build 53 `config.js`. Bumping `CACHE` in `sw.js` installs a new worker; on `activate` it deletes every cache except `CACHE` and `LIBS`. `panels.js` shows the "new version available" banner on `controllerchange`.

Requests whose path ends in `.mp4` or `.webm` are not handled by the service worker at all (the `fetch` handler returns without calling `respondWith`), so the browser loads them itself. Browsers fetch video in pieces (range requests answered with partial `206` responses), and the Cache API can't store those, so the demo video is not in `SHELL` and is never available offline. `media/demo-poster.jpg` is not in `SHELL` either; it goes through the normal network-first handler and is saved once it has loaded.

Libraries from the hosts in the `CDN` list (`cdnjs.cloudflare.com`, `cdn.jsdelivr.net`, `unpkg.com` and Tesseract's language data host `tessdata.projectnaptha.com`; the Google Fonts hosts were removed, as the fonts are self-hosted) are cache-first in a separate cache, `LIBS = "lpn-libs-v2"`, because their versioned URLs never change. The rules:

- **What is saved:** only complete downloads (`res.ok`). An opaque (unchecked, `no-cors`) response is saved only for Tesseract's own files (`tesseract` or `tessdata` in the address), as those can only be fetched that way; `dropOcrCache()` clears them if the reader fails.
- **What answers a request:** a saved opaque copy is never used to answer a request that isn't `no-cors` (such as a script loaded with `crossorigin` and an integrity hash); the worker fetches a fresh copy instead.
- **Why v2:** `lpn-libs-v1` could hold a failed or unchecked download. Renaming the cache makes the `activate` step delete v1 once, so every library is downloaded fresh after this update.

## Theming

**Follow phone (build 46).** `theme` can carry `follow: true`. `themeNow()` returns the colours to use: with `follow`, `THEME_LIGHT` (`#eef1f6` / `#2563eb`) when `matchMedia("(prefers-color-scheme: dark)")` doesn't match and `THEME_DEFAULT` (`#0c1830` / `#ff8a2a`) when it does (or when `matchMedia` isn't there); otherwise `theme` itself. `applyTheme()` works from `themeNow()`. A `change` listener on that media query (`addListener` on older browsers) re-applies the theme and calls `window.themeSync()` while `follow` is set, so the Settings boxes update. In `initSettings()`, `#setFollow` sets `theme = {bg, ac, follow: true}` when ticked; when unticked, and before any picker or valid hex change (`own()`), the colours showing are copied into a plain `{bg, ac}`. Quick themes set `{bg, ac}` (no `follow`), and **Reset to default colours** removes `lpntheme`. `saveTheme()` stores `theme` as is, so `follow` is saved; on load it is kept only if it is exactly `true`.

`applyTheme()` derives every colour token (`--paper`, `--ink`, `--mu`, `--line`, `--sel`, `--onac`…) from two user colours, background and accent, by mixing them with white or black depending on whether the background is dark. Pallet-type colours have separate light and dark values. See `DESIGN.md`.

Since build 41 two tokens are for contrast:

- `--bd`: the border of inputs, selects, buttons and text areas, `--paper` mixed 42% towards white (dark themes) or 48% towards black (light themes), at least 3:1 against the paper. `--line` stays for dividers and table rules.
- `--act`: the accent used as text and outlines (panel headings, the version badge, `.linkbtn`, the focus outline and focused border). It starts as the accent and is mixed towards `--ink` in steps of 10% (up to 10 steps) until its contrast is at least 4.5:1 against both `--paper` and `--bg`. A focused primary button (`button.p`) gets an `--ink` outline instead.

The CSS falls back to `--line` and `--ac` where these aren't set.

**Mid-tone backgrounds (build 56).** `dark` is no longer `lumOf(bg) < .3`: it is true when white text would have more contrast on the background than black text (`1.05 / (L + .05) > (L + .05) / .05`), so mid greys such as `#8c8c8c` get dark text. After the token table is built, a block with `r(a, b)` (the contrast ratio) and `pole` (white for dark themes, black for light):

1. moves `--paper` away from the text colour (towards black on dark themes, white on light) in steps of 10% until `pole` on it is at least 4.6:1;
2. moves `--ink` towards `pole` in 10% steps until it is at least 7:1 against both `--paper` and `--bg`, and `--mu` (grey text: hints, placeholders, notes) until it is at least 4.5:1, each as far as 10 steps allow.

Since build 62 `--wn` (the warning colour: refused tags and counts, the reminder card border, the seal note, testing notes) is then moved towards `--ink` in 10% steps (up to 10) until it is at least 4.5:1 against both `--paper` and the background. `--act` is then worked out against the adjusted `--paper`. For the quick themes nothing moves (the checks hold navy and orange at `--ink #ecedee`, `--mu #a3a7b0`, `--paper #1f2a41`).
